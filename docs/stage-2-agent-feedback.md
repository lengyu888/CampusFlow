# 第二阶段：真实工具摘要与失败恢复

本阶段让用户看清本轮查了什么、请求为何没有完成，以及提案是否需要核对。沿用第一阶段的完整计划预览和现有主题；不重做其他页面。

## 可见变化

- 每轮回答附带可展开/收起的工具摘要：课程和事务数量、空结果、工具失败、数据源不可用、待确认提案等分别呈现。天气工具明确标为演示数据。
- 等待期间只显示“正在处理请求”，整轮返回后才显示实际工具记录，不伪造实时步骤。
- 请求失败有独立提示，保留原输入。空输入框自动恢复；等待时输入的新草稿不会被覆盖，也可稍后手动恢复原输入。
- 下一轮回答不会清空之前的待确认提案。已确认/已取消的卡片保留结果；连续点击和发送/确认并发受到保护。
- 确认同时核对提案 ID、状态和 `applied`；不会仅凭接口返回 HTTP 200 就显示成功。
- 操作结果不明时，只提供“核对状态”和“查看规划”，不会自动重发确认或取消。状态读取后仍要求核对实际任务，不把 `pending` 解释为“完全没有写入”。
- 登录失效与模型 API Key 失效分别提示，提供“前往我的”入口。不会把旧接口的任意 401 都当作登录过期。

## 接口改动与兼容

1. `tool_traces` 保留原字段，新增可选 `status` 与 `display`。后者只有 `label/state/summary`，由白名单规则生成，原生组件不接收原始参数或原始结果。
2. `display.state` 为 `success/empty/error/unavailable/pending/unverified/demo`。`success` 只表示有可汇总的返回数据，不表示任务已执行。未知工具、旧服务缺摘要或异常结构降级为“未核验”。
3. 原有字符串 `detail` 保留，部分错误新增顶层 `code`，区分登录、模型凭据、超时、提案不存在、已处理、执行失败及不支持操作。客户端仅在 Agent 相关接口采用新错误映射；其他页面的原错误文案保持兼容。
4. 新增 `GET /api/v1/actions/{proposal_id}`，只读取当前用户所属提案。它是状态查询，不是带业务对象 ID 的写入收据。
5. 保留真实 `ToolMessage.status`，错误工具消息不能被当作有效待确认提案。电费工具的时间值序列化为 ISO 字符串，避免整份工具结果退化为不可解析字符串。
6. 现有存储逻辑未实现修改/删除提案的执行，因此界面禁用此类确认，接口也在写入前明确拒绝；仍可取消提案或到规划页手动操作。

摘要不会复制个人校园档案、姓名学号、成绩、余额、房间、订阅链接、凭据和原始异常文本。这里保护的是新增摘要展示，未声称整个模型回答或原始 API 响应已经完成隐私改造。

## 验证

使用当前分支源码、本地 ASGI、隔离 SQLite 和合成网络响应，不调用真实云端模型或校园账户。

```sh
cd agent-service
PYTHONPATH=src python -m pytest -q
cd ../arkui-x-client
npm run check
node scripts/test-agent-feedback.mjs
node scripts/test-agent-interactions.mjs
```

- 客户端逻辑测试：22 项通过，包括真实 API 方法及 AgentPage 非 UI 方法的模拟网络行为。不是 ArkTS 编译或原生渲染测试。
- 客户端静态检查：24 个 ArkTS/TS 文件、17 个配置文件通过，覆盖工程、导入、配置和已有接口引用。
- 后端：207 项通过、2 项真实模型集成测试按项目配置未运行；摘要覆盖 13 个工具的有效、空、不可用、错误、畸形和敏感字段场景；API 契约覆盖取消、重复确认、失败、用户隔离及错误码。
- 改动涉及的 Python 文件 Ruff 与 `git diff --check` 通过。

## 待设备验收

当前机器没有匹配的 DevEco/ArkUI-X SDK、Java 和模拟器，未运行 HAP 构建，也未验证鸿蒙、Android、iOS 的原生效果；以 Draft PR 交付。

在三端分别运行以下场景，记录系统、构建版本、实际响应与屏幕表现：

| 场景 | 应看到的结果 |
| --- | --- |
| 正常查询 | 工具摘要与本轮返回数量对应，可折叠；下一轮不覆盖上一轮记录 |
| 空数据 | 明确“暂无数据”，不推导为全天空闲或服务失败 |
| 工具失败 | 显示失败或不可用，不展示原始异常、密钥或个人档案 |
| 取消提案 | 卡片标为已取消，不能再确认；正常取消不新增任务 |
| 确认断网或失败 | 提案保持可见，只读核对状态；前往规划检查可能的部分写入 |
| 重复点击确认 | 客户端只发一个 POST；已处理提案不能再次执行 |
| 请求等待中编辑 | 新草稿保留；失败后原输入也可复制、恢复 |
| 登录或模型凭据失效 | 两种提示不同，模型错误不触发退出登录 |

## 仍保留的边界

- 当前会话中的工具摘要、提案卡片与恢复状态尚未做手机本地持久化，重启后不恢复；原历史接口没有这些完整关联。
- 存储层的失败部分写入、确认时冲突复检、跨请求并发和完整执行回执仍由后端协作线处理。本阶段只防止原生端盲目重发，不宣称解决事务原子性。
- 第三阶段的窄屏、长回答、键盘及地图适配尚未开始，需要用户再次说“继续”。
