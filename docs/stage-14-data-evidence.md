# 第十四阶段：真实数据与依据

基线为第十三阶段 `feat/stage-13-agent-runtime`，本阶段分支 `feat/stage-14-data-evidence`。继续使用共享 ArkUI-X 页面与业务逻辑，不安装原生环境，不进行设备测试或真实模型评测。

## 用户能得到什么

- 正常账号只看到自己确认的课表；未录入或清空时保持空态，不再自动补入开发样例。导入后的课程来源取自最后一次成功保存或订阅同步，并与课程内容一次读取，避免并发更新混用新旧版本。
- 校园、路线、校园服务、课表和 Agent 工具结果可展开来源，查看记录时间、缓存期限、限制说明及可复制的公开链接。页面停留时也会重算过期状态。
- 天气来自 Open-Meteo 公开接口。默认明确写为“杭州城市级预报（非校园定位）”，展示当日温度范围及最高降水概率；没有匹配地点、超出预报范围或查询失败时给出原因，不显示固定晴天等样例结果。
- 地点开放状态无法实时核实时显示“未知”；路线继续提供示意路径，但明确步行时间、距离均为人工估算。历史种子通知不进入正常通知查询，也不计入正式通知数量。
- 其他学校、校区没有匹配校园数据包时明确说明，不把杭电下沙资料套用过去。用户历史纠错记录仍可查阅。

## 来源与有效期

统一 `DataEvidence` 包含来源 ID、名称、类型（用户/远端/参考/演示）、状态、真实记录时间、缓存到期时间、公开链接和说明。旧版本未记录时间的资料保留“待核验”，不会把迁移时间写成资料更新时间。

课表手动保存时间表示用户确认时间，不能代表学校实时发布；订阅课表建议超过 24 小时后刷新。HDUHelp 按资源设置刷新策略：余额及即时教室/电费 5 分钟，预约 10 分钟，考试及部分活动 1 小时，成绩等 24 小时，身份资料 7 天。这些期限是应用缓存使用策略，不是提供方对数据正确性的保证。过期缓存可在校园服务中带来源回看，但 Agent 的查询工具不会把过期值当作当前值。

静态校园图保留数据包原声明时间，状态为参考、待核验，不虚构官方现场核验。来源链接只允许不含账号、密码、查询参数或片段的公开 HTTPS 链接；用户令牌不进入来源面板。缓存解密失败作为同步错误展示。

## 天气接入

使用 [Open-Meteo Forecast API 官方文档](https://open-meteo.com/en/docs)，固定 HTTPS 域名，请求 Asia/Shanghai 日预报，严格校验日期、时区、单位、数值及 WMO 天气码。默认杭州坐标 `30.29365,120.16142` 由 Open-Meteo 地理编码结果核对，仅代表城市级查询点，不能当作下沙校区测量值。响应网格位置也可能与查询点不同。

每次请求上限 8 秒、响应 64 KiB；缓存最多 15 分钟并在预报当日结束前失效。刷新失败时旧记录仍保留原时间，状态过期且 `available=false`。不发送账号、学校名称、设备位置等用户信息。另一个校区可通过 `.env.example` 中五项 WEATHER 配置明确映射。当前公开免费用法适用于本教育项目；来源及许可依据见 [Open-Meteo 使用条款](https://open-meteo.com/en/terms)。没有新增依赖或天气付费凭据。

## 实际检查与限制

后端完整离线回归 497 项通过，2 项真实模型用例按已有标记排除；客户端 463 项通过；静态检查 47 个 ArkTS/TS 源码、17 个配置通过，Ruff 与差异检查通过。新增测试覆盖数据来源与课程原子快照、旧库恢复、账号/校区隔离、过期状态、天气异常、页面接线与请求生命周期。离线测试使用真实 SQLite/ASGI 和可控 HTTP 响应；天气另外执行过一次无密钥公开接口查询并获得有效、带时间的响应。该请求只证明此次天气接入可用，不证明未来接口可用性或天气事实完全准确。

没有调用真实云端语言模型，没有核验个人 HDUHelp 在线数据，也未进行鸿蒙、Android、iOS 原生编译、签名、安装或设备测试。这些不能由 Node/Python 检查代替。
