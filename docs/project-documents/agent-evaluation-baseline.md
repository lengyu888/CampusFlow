# Agent 固定验收基线

建立日期：2026-10-18，Asia/Shanghai。用于比较后续 Agent 优化，保留现有业务行为。

## 范围与判定

[场景清单](../../agent-service/evaluations/agent-baseline.json)当前包含 39 个稳定编号的场景，
记录代表性输入、前置条件、预期工具、允许的业务效果、判定标准及对应 pytest 检查。
覆盖日期、课程、来源时效、天气、知识、路线、提案、权限、失败、预算、取消、恢复、上下文和偏好。
清单中的输入是在线验收题目；离线运行器执行关联的代码契约测试，不会把这些自然语言问题交给真实模型。
具体离线数据由所关联测试的 fixture 定义，部分场景会展开为多个参数用例。

两种结论分开记录：

- `offline_status`：关联的代码检查是否通过。参数用例必须全部通过；跳过、缺失不能记为通过，
  pytest 非零退出也不能生成整体通过结果。
- `model_quality`：本轮统一为 `not_evaluated`。离线替身指定的工具调用不证明模型会选对工具，
  提示词日期检查不证明模型会正确换算日期，来源卡片正确不证明自由回答的每句话有依据。

`expected_tools` 是在线评审参考，允许有用的辅助只读查询；不是必须严格相同的调用序列。
空数组表示该契约没有指定业务工具，可能使用测试专用工具或只检查运行服务。
提案确认由应用接口完成，不能解释为模型具备确认工具。
初版 CF-28 刻画旧约束丢失。上下文优化后，它已改为正向检查旧约束在裁剪后仍通过结构化资料进入模型输入。
CF-31 至 CF-38 覆盖修改/撤回、全清、无效资料、工具续轮、隔离、持久重载和兼容入口。
CF-39 在真实运行的模型请求边界验证：旧历史裁剪后，四字符围栏内的三字符围栏示例
不能修改或全清原有约束。CF-26 同时检查工具启动前与等待工具中的真实超时取消路径。
这些检查验证输入边界，不能替代模型是否遵守约束的在线评测。

## 重复执行

在 `agent-service` 目录运行：

```powershell
.\.venv\Scripts\python.exe tests/baseline_runner.py --output data/evaluations/agent-baseline-v3.json
.\.venv\Scripts\python.exe -m pytest tests/test_baseline_runner.py -q
```

使用当前 Python 环境，无新增依赖。运行器固定排除 integration 标记，复用现有测试的离线禁网规则，
不读取个人账户数据库、不调用真实模型或校园服务。测试数据库由 fixture 在临时目录创建。
输出包含上海时区时间、每个场景及其实际匹配的检查数量，以及完整场景清单的 `dataset_sha256`。
初版报告没有该 hash 字段；比较时同时检查报告内保存的场景标准，不能混用不同标准的通过率。
报告默认示例位置位于已忽略的 `data/`；临时 JUnit 文件在运行后自动清理。
输出路径由调用者指定，重新运行会覆盖该路径；需要比较时使用不同文件名。
运行器清除子进程的 `PYTEST_ADDOPTS`，显式覆盖 pytest 的 `addopts` 并禁用测试缓存，
避免环境或配置中的筛选条件隐藏失败参数用例；真实子进程回归覆盖这两种筛选来源。

## 上下文核查

当前持久运行在每次模型调用前按字符预算保留近期完整问答回合，计入系统输入、
当前回合和工具 schema。当前必需输入超限时失败；不拆开正在进行的工具交互。
较长工具结果向模型提供带截断标记的摘录，返回客户端的完整结果另行保留。

新增 CF-27/28 在实际 `AgentService.run` 的供应商请求边界检查：

- 近期“每天最多复习两小时”会进入模型输入；运行不擅自改写持久历史。
- 优化前，旧回合超出预算时约束退出输入；优化后，支持的显式约束保留在有来源编号的结构化资料中，原始历史不改写。

当前没有通用摘要或跨会话长期事实提取；新增的是有限语法的同一会话学习约束投影。
`SessionSummary` 是会话目录元数据，不是聊天内容摘要。
用户主动设置的学习偏好有独立存储和提示注入，不能覆盖所有聊天约束。
结果查询恢复也不等同于从中断的模型/工具步骤继续执行。

时长上限和时段约束的修改、撤回、全清按用户原文顺序重建；投影独立于近期回合裁剪，
不引入持久记忆缓存或额外模型调用。两个入口都检查模型输入预算，旧 chat 也检查工具续轮。
具体支持示例、限制和删除语义见 [会话约束记忆说明](session-context-memory.md)。

## 真实模型评审规则（尚未执行）

使用隔离测试账户和固定数据，记录代码版本、模型 ID、供应商、日期时区、实际输入、
前置课程/任务/授权状态及资料版本。CF-01 离线固定时钟与在线真实时钟不同，在线应冻结时钟
或在提交前人工记录对应日期和预期工具日期参数，不直接复用旧日期答案。
并发、过期、取消等场景须按关联测试构造条件，不能仅发送题目便认为覆盖。

每题保存用户可见回答、真实工具轨迹、提案及确认前后业务状态，并分别评审：

1. 是否调用适当工具，日期和目标 ID 是否正确；无权限或资料缺失时是否如实说明。
2. 回答是否满足本轮明确约束和已保存偏好；只查询/建议时不得创建提案。
3. 引用是否支持对应陈述，是否区分过期、静态参考、演示和实时数据。
4. 创建/修改/删除是否经确认，重复或并发确认是否只产生一次预期业务效果。

补充两项对照输入：“只给我复习建议，不要保存”和“创建同样的复习待办”，检查提案边界。
每题记录通过/失败/未评测及原因；控制性指标要求全部满足，质量指标报告分母和未评测数量。
延迟、调用次数、供应商实际返回的用量另行记录，未返回 token 用量时标为未知，不能用字符数冒充。
按相同数据和规则至少重复三轮，再比较工具选择、约束、引用及延迟变化；当前不设没有基线支持的质量分数门槛。
真实服务和付费调用应作为后续单独验收执行，不能把本次离线报告改称在线评测报告。
