# 第九阶段：整体设计与可点击原型

## 解决的问题

第八阶段已有课表、完整计划、冲突改期、语音交互和本地历史，但入口分散，核心页与设置页的视觉不统一，查看某个计划仍容易只跳到列表。此阶段确定新的使用路径与组件规范，为后续 ArkUI-X 实现提供可操作的参照。

- 四主入口：今日、Agent、计划、校园。头像进入个人，能力管理归校园，历史归 Agent。
- 今日以“下一项安排—当天时间线—待安排”为重点；计划分日程、目标计划、全部待办。
- Agent 回答与提案关联，完整内容可展开，确认和回执可理解；保留语音转写先编辑再发送。
- 首次引导、课表维护、校园服务、能力、个人和历史均有结构与异常状态约定。
- 跨页保留草稿和浏览状态，返回到实际来源；旧请求、音频和账号清理规则保持。

## 查看

打开 [单文件交互原型](../previews/stage-9-campusflow.html)。文件内包含示例数据、样式和交互，无需安装依赖，不连接后端、模型或真实账户。新版与当前版的对照使用同一组合成校园安排；可通过重置恢复初态。

“当前版”根据 `6c514b0` 的三个核心页面近似复现，个人仓库 `3043f0c` 的功能代码与其一致。它不是第五阶段对照中更旧的第四阶段，也不是设备截图。新版是第九阶段设计方案，ArkUI-X 源码落地属于第十、十一阶段。

原型中的录音、转写、播报、进度、数据来源、确认与改期都用于演示交互；示例回执仅修改页面内存。它不证明实际模型、数据库、系统录音/播放/通知或三端运行已完成。原型中的来源标注不能作为真实校园信息使用。

## 验证记录

已使用现有 Chrome 与 Playwright 完成 12 条浏览器旅程：同数据对照、草稿与建议、计划视图和详情返回、日期草稿隔离、提案确认、语音模拟编辑、改期快照失效、改期不复制、导入预览与放弃、首次手动录课确认、离线限制、320 px 大字号及键盘占位。全部通过，无脚本错误、无网络请求。

另检查 1440×1050、375×812、812×375 三种浏览器视口，未见页面横向溢出；人工查看三个核心页对照和窄屏截图。此处仅是网页设计原型的验证，不代表 ArkUI-X 或系统键盘已验证。

可复跑：`PLAYWRIGHT_MODULE=<现有 playwright 路径> CHROME_EXECUTABLE=<现有 Chrome 路径> node docs/previews/check-stage-9.cjs docs/previews/stage-9-campusflow.html <临时输出目录>`。脚本不会安装依赖或浏览器。没有安装原生环境或执行原生编译、设备验证。
