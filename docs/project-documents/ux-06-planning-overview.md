# UX06：计划检索、一周安排与课内提醒

## 具体有什么用

计划保留日程、目标计划、全部待办三个入口。课程和任务改为紧凑行，完成控件与详情入口分开；目标计划仍保留阶段和任务层级。

全部待办可按标题或地点查找，叠加状态、日期条件，再选择时间或创建顺序。结果明确显示找到多少项；没有任务和没有匹配结果分别说明。同名任务仍按真实编号区分，分页不会丢掉其余任务。

周总览展示北京时间周一至周日的实际内容，空日也保留。跨日任务按当天交集展示，全天与未定时事项单列。窄屏采用七天列表，不把七列压成难以点击的小格。返回详情后保留查找条件和所选周；“安排这一天”把完整选中日期交给助手草稿，不自动发送。

## 可以在课上做，也需要说清楚

- 普通课程冲突：显示任务、课程、日期、地点、教师及实际重叠时间；可以查看任务或生成规则改期预览。
- 已确认的课内安排：保留原时段，不自动挪走。
- 课表或任务变化后待核对的安排：显示新依据，通过任务编辑预览重新明确确认。
- 缺少时段的事项：解释未核对原因，不能显示成“没有冲突”。

查看任务按编号定位。课程详情绑定课表版本、完整六字段和该快照内的重复序号；课表已经变化就提示重新选择，不能按同名课猜测目标。维护课表继续使用既有版本保护链路。

旧服务端没有提供课内确认分类时，界面会说明分类缺失，不把缺字段当成已经核对的空结果。扫描只覆盖尚未结束、时段完整的未完成任务；改期仍是现有规则，没有称为全局最优。

## 预计负荷的含义

分别列课程占用、已排任务和合并占用，按时间区间并集计算，课内安排不会重复加时。完成的定时任务仍属于已排日程；这些数字不是实际学习时长。全天、未定时或缺结束时间的事项不伪造时长。

候选预览按准确任务编号替换原时段后再计算，确认前不修改计划。手动全天候选沿用真实来源规则。只有用户明确启用的每日任务目标才参与温和提醒，课程时间不算进该目标，不根据提示自动删改任务。

课表、计划与学习偏好分别读取；某个来源失败保留其已有内容并注明不完整，不把旧缓存或空回包说成完整空闲。

## 验证范围

实际 ArkTS 逻辑测试覆盖 100 项查找、稳定排序、上海自然周、偏移与跨日、课程版本引用、精确候选替换和负荷并集。后端沿用 UX05 已验证实现，另跑课内安排与重新规划相关回归。真实鉴权 ASGI/SQLite 合成回包交给客户端校验器核对四类结果及具体交集；独立 GET 不被当成同一事务快照。
