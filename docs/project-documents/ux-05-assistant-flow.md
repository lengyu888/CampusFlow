# UX05：会话接续、可解释提案与语音输入区

## 用起来有什么变化

- 助手顶部显示正在讨论的主题，新对话与历史有独立入口。历史中的“继续此会话”先读取当前账号的服务端正文；离线副本仍只供回看。
- 当前输入按会话保存。运行中的会话可以在草稿落盘后切换，停止本机轮询不等于取消服务端运行；回来核对原运行编号。提案确认或许可修改的结果未知时，先核对结果，避免丢失待处理事项。
- 输入区保留语音、文字、发送。模型选择在单独面板里，当前可用性读取模型目录。语音先给出用途说明，识别文字仍需采用、编辑和手动发送；不会因为切换会话覆盖另一份输入。
- 提案先看任务数量、明确起止范围、截止日期、缺失时间与冲突，再展开本轮实际工具来源。多个任务的最早至最晚时间不是连续占用时长，也不展示虚构的思考过程。
- 每个候选可明确设置“可在上课时完成”。服务端返回替换预览，随后显示具体课程与重叠，用户再次核对并确认。历史同意、模型回答或本地开关都不能替代这次确认。
- 可以取消原候选后调整日期、时长和偏好。原候选取消得到核对后，调整描述才进入输入草稿，由用户再次发送生成新候选；未知取消不被当成已完成。

本阶段不增加装饰性的“方案 A / B”。只有实际生成的候选才允许展示和确认。

## 会话与写入边界

`GET /api/v1/sessions/{id}/context` 返回当前账号的摘要、完整文字、上下文版本及该会话真实活动运行。成功历史才构成可接续会话，未完成首轮通过运行编号恢复。

新运行请求增加可选 `session_mode`、`expected_context_revision`。新客户端发送明确模式；续聊必须带刚读取的上下文版本。服务端在接受、读取模型输入和保存结果时核对版本。另一端新增内容后会保留输入并提示刷新，不自动换版本重发。成功快照里的 `input_context_revision` 是本轮输入条件，不能当成下一轮的新版本。

旧客户端省略这两个字段时，原四字段指纹保持不变；相同运行编号的已保存回执仍先返回。同步 `/chat` 同样使用冻结历史，并将一问一答原子写入，避免只有半轮历史。

删除会话会在同一事务内核对活动运行、清理记录并保留账号内的删除标识。迟到回答或新运行编号不能把已删会话重新写回来。标识不保存对话正文。

历史正文恢复为只读文字。旧提案、工具参数或看似 JSON 的回答不会复活成可执行操作。新的确认、取消与课内许可替换在提交前保存精确恢复指针；恢复先查询，不凭本地记录自动再执行。

## 原型与验证

[助手与课内安排交互原型](../previews/ux-05-assistant.html) 使用合成数据，支持模型面板、语音说明、保留草稿、新对话、逐项提醒以及键盘占位。它用于浏览器布局核对，不是应用运行截图。原型没有网络写入。

实际校验分为：

- 后端 SQLite / ASGI：版本竞争、双会话归属、冻结模型输入、删除与迟到完成、事务回滚、旧请求指纹。
- 实际 ArkTS 逻辑：会话草稿隔离、原请求恢复、提案未知结果、语音与账号代次、接口方法和安全错误文案。
- 跨语言合同：真实鉴权 ASGI 合成回包交给实际 ArkTS 会话/运行校验器与 DraftStore，检查字段和持久化一致。
- 浏览器原型：窄屏、大字、多行输入、键盘占位下最近回答可达，课内许可与再次确认不混为一步。

最终检查记录见 `../evidence/ux-05-checks.json`。未安装原生环境，未进行原生编译、设备键盘/麦克风/播报验证或真实付费模型评测。原生效果与三端安装运行交由学长设备验收。
