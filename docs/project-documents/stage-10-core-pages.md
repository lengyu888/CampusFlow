# 第十阶段：三个核心页面落地

## 具体用途

- 首页按上海时间合并课程和定时待办，突出正在进行或下一项安排；全天事项与待安排事项分开，未安排日期不再被算作今天必须完成。点击任务或目标直达对应 ID 的完整详情。
- Agent 回答与该轮提案关联，已处理提案显示简短回执，完整任务内容仍能展开；外部建议先保留原草稿，提供明确的采用方式。模型选择下沉，阅读旧回复时不强行滚到底部。
- 计划区分日程、目标计划、全部待办；真实冲突摘要前置，核对和改期仍使用同一个控制器。日历浏览与待办草稿日期继续分离。
- 四主入口为今日、Agent、计划、校园；能力、个人、历史和校园服务作为二级页面。嵌套返回回到实际来源；主页面常驻保留输入和浏览状态，账号退出清理导航与缓存。

## 代码与效果参照

本阶段将 [第九阶段原型](../previews/stage-9-campusflow.html) 的核心结构实现为 ArkUI-X 组件，没有使用网页替代原生主页面。统一颜色、字号和间距来自 [设计规范](design-system.md)。校园入口先连接现有能力、服务、路线和设置，完整课表维护及二级页面统一属于第十一阶段。

核心文件：`pages/HomePage.ets`、`pages/AgentPage.ets`、`pages/PlanCenterPage.ets`、`pages/Index.ets`；共享逻辑：`utils/DailyAgenda.ets`、`utils/AppNavigation.ets`。跨页详情只按实体 ID 定位，无法找到时明确提示。当前 Agent 旧确认接口还没有返回实体 ID，因此使用“查看计划列表”，不会把 proposal_id 猜成 plan_id。

网页对照仅作为视觉参照，不是本次 ArkUI-X 运行截图。未安装原生 SDK、模拟器，没有进行原生编译或三端设备运行；实际触控、系统键盘、字体缩放和原生布局仍需原生环境验收。
