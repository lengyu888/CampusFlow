# 第十一阶段：全应用体验与课表维护

基线：第十阶段个人提交 `9699359`，原项目提交 `7214a2d`。本阶段在两个仓库各使用 `feat/stage-11-unified-experience` 分支，PR 以各自第十阶段分支为基线，不修改或合并 `main`。

## 用户能获得什么

- 「校园 → 我的课表」与「个人设置 → 课表维护」均可再次进入同一份账号课表。支持手动增加、单次编辑、周期展开、移除、订阅预览合并，保存前查看完整草稿。课程和候选分 10 项分页，超出首屏内容仍可访问。
- 离开课表页保留课程草稿、编辑表单和候选；返回核对服务器版本。只有最终确认才更新账号课表，清空须单独确认。导入预览可编辑后保存，保存不会重新抓取链接或重置个人资料。
- 保存遇到断网时保留本次操作标识和完整提交，先查回执；尚无记录时只能用同一标识、同一内容重试。旧版本不覆盖新课表；收到历史成功回执后还会读取当前版本，发现随后更新时明确提示。
- 登录、首次引导、能力管理、个人设置、历史、校园服务与导航页统一字体、间距、控件和反馈。设置拆成账号、模型、数据连接、偏好，账号与模型密钥分开提交。能力权限展开后才能安装或启用。
- 历史标明本机与服务端来源，保留完整正文、已有离线及删除保护。校园服务保留筛选，区分加载、查无记录与失败，失败可重试；占用详情失败不破坏教室列表。较长教室/占用列表可继续展开。
- 校园服务与路线页切走后忽略旧请求回包；路线起终点改变会使旧路线失效。校园数据未连接时有实际的设置入口。

## 后端与数据边界

`GET /api/v1/me/timetable` 返回课程与内容摘要版本；`PUT` 携带 `entries`、`expected_revision`、UUID `operation_id`、`confirm_clear`，在同一 SQLite 事务内写课表和账号隔离的操作回执。`GET /api/v1/me/timetable/operations/{operation_id}` 可核对历史结果。同一操作异内容拒绝，重复同内容返回原回执。

订阅抓取在数据库事务外执行，写入前同时核对课表版本与订阅连接；课程和订阅信息原子更新，避免旧同步覆盖手工编辑或恢复已断开的连接。账号明确清空课表后，查询日程不会回退样例课程。演示/真实信息的完整分离与统一来源展示仍属第十四阶段。

草稿与未完成操作保留在当前登录会话的页面实例中，退出或进程终止会释放；不声称课表草稿已具备跨重启持久恢复。已有本地对话历史持久化不受此限制。
