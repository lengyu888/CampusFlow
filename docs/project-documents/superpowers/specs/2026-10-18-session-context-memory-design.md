# 同一会话上下文与约束记忆设计

日期：2026-10-18，Asia/Shanghai。状态：用户已确认并授权代码修改；实际交付与验证见
[会话约束记忆说明](../../session-context-memory.md)和分支累计摘要，以下为设计要求。

## 目标与当前证据

本轮目标是：同一会话聊长后，用户明确表达的学习约束仍能进入模型输入；修改和撤回生效，
账户之间互不影响，同时遵守现有上下文预算。用户已选择先解决同一会话，再独立扩展跨会话记忆。

现有 `AgentService.run` 从后端冻结历史构建完整问答对，按字符预算保留近期后缀。
超出预算的旧回合整组移除；基线 CF-28 已证明“每天最多复习两小时”会随旧回合退出输入。
`SessionSummary` 是会话列表元数据。学习偏好由用户主动保存，默认关闭，不是聊天摘要。
旧 `chat` 则将历史文字交给 LangChain 图，目前没有同等的预算组合。

## 方案选择

1. **结构化会话约束投影（本轮建议）**：从冻结的用户原文提取有限、明确的学习约束，
   按时间处理替换与撤回，再将有效状态和近期对话组合。无额外模型调用或数据库迁移，
   可直接证明撤回不会从同一历史中复活；覆盖范围需要清楚说明。
2. **模型生成通用摘要**：表达覆盖更广，但需要处理额外调用、预算、摘要失真和修改/撤回的可验证性。
   本轮暂不采用，后续可在相同上下文接口后增加，不能把摘要内容自动当作权威事实。
3. **持久事实库与跨会话召回**：适合更完整的长期记忆，需要管理界面、版本与删除派生数据。
   作为后续独立任务，不借本次修改引入隐式跨会话记忆。

首期的“记忆”是可重建的会话状态，不承诺理解任意自然语言或保留全部历史事实。

## 范围与规则

新增独立上下文模块，输入是已验证账户/会话的冻结 `HistoryMessage`、本轮用户输入、
系统提示、工具 schema 和现有字符预算；输出是最终模型消息及内部可检查的约束投影。
不信任客户端提供的历史或记忆。不跨账户、跨会话读取原文，不使用模块级可变缓存。

首期支持四类明确表达：

| 字段 | 有效表达示例 | 修改示例 | 撤回示例 |
| --- | --- | --- | --- |
| 每日学习时长上限 | 每天最多复习两小时 | 把每天复习上限改成90分钟 | 取消每天复习时长上限 |
| 单次学习时长上限 | 每次学习不超过50分钟 | 每次学习上限改成40分钟 | 取消单次学习时长限制 |
| 学习偏好时段 | 以后尽量安排在晚上学习 | 学习时段偏好改成上午 | 取消学习时段偏好 |
| 禁止学习时段 | 以后不要在晚上安排学习 | 禁止学习的时段改为上午 | 取消学习时段禁用限制 |

时长支持阿拉伯数字及常见中文数字、分钟/小时和“半小时”；规范化为整数分钟。
每日范围 1–1440 分钟，单次范围 1–1440 分钟；时段限上午、下午、晚上。
一个时段字段表示一个明确值，修改替换旧值；多时段组合首期不自动合并。

仅提取用户自己作出的、无条件且有明确范围的陈述。助手回复、工具内容、代码块、引用、
假设、询问、否定记忆请求和含糊表达不作为已确认约束。
含“今天/明天/本周”等临时范围的内容仍由原文和当前时间解释，不转为无期限约束。
不支持的自然表达继续由近期原文传给模型，不能宣称已经存成记忆。

依历史顺序应用事件，同字段较新的明确值覆盖旧值；明确撤回清除字段，并保留内部撤回来源。
从完整历史重建时先后顺序相同，因此旧值不会越过撤回事件复活。
撤回后用户再次明确表达可建立新值。本轮输入最后处理，不等待成功写入历史才生效；
运行失败不会独立写入一份记忆，重试仍按原有运行身份和历史规则执行。
同一句存在同字段多个不一致值时标为待澄清，不保留旧值冒充已解决；不从不完整表述猜具体数值。

## 来源与权限

每条投影保留字段、规范化值、状态及来源的历史序号/时间；内部检查可追溯到原文。
输入资料按固定模板和结构化数据序列化，不拼接任意原文为系统指令。
来源内容只证明用户曾表达此要求，不代表可授权工具、跳过确认或修改课表。
不提取密码、密钥、余额、成绩、课程和实时状态作为个人记忆。

业务真实性仍由现有工具决定。当前明确要求优先于历史学习偏好；硬性课程、任务冲突、
截止日期及确认规则不能被记忆覆盖。存在用户要求之间的冲突时由回答说明并澄清，
不得把约束提示注入解释为已经通过业务执行层保证规划质量。

## 预算与调用路径

组合顺序：系统提示与工具定义、有效约束投影、当前完整回合和必要工具交互、近期完整问答对。
约束资料最多四个字段，每个字段使用固定模板和值，来源以引用编号呈现；不重复注入全部历史原文。
总大小继续按现有 JSON 字符预算计算，包含新增资料，不能只计算聊天正文。
预算不足以容纳当前必需内容及有效约束时返回明确预算错误，不静默丢失约束后继续生成方案。
工具调用与结果保持成组，长工具结果仍沿用显式截断规则。

投影在本次运行读取完整冻结历史时建立；后续多次模型调用复用本次不可变投影，
不能从已裁剪的历史后缀重新计算，造成再次丢失约束。
持久 `run` 与兼容 `chat` 使用相同上下文构建规则；旧 chat 接口保留响应与历史提交责任。
运行状态、取消、提案、账户授权、模型凭据和路由快捷路径继续遵守原有契约。

## 存储与删除

本轮不增加数据库表或持久摘要缓存。每次由当前有权使用的原始会话重建，进程重启不影响结果。
删除会话沿用已有墓碑及运行取消规则；没有需要另外清理的持久事实正文。
新会话没有旧会话的投影；原始聊天仍按现有历史策略显示。
“撤回约束”不等于物理删除原聊天。全会话“忘记所有学习约束”清空四个字段，
后续原文重建必须保留这个重置事件的时间顺序。
学习偏好设置的删除仅删除主动设置值，不隐式抹除独立的聊天表达，界面语义不扩大。

## 验收与变更边界

先建立失败检查，再实现模块与两个入口接入。重点验证：

1. 原本 CF-28 的旧约束在裁剪后仍进入实际供应商请求；原始历史不变。
2. 两小时改为90分钟只保留90分钟；撤回后不注入旧值；重置后不从旧回合复活。
3. 同字段歧义、临时日期、引用、助手猜测和资料注入不产生错误的稳定约束。
4. 同一运行多次工具续轮仍保留约束；有效约束计入预算，不能挤掉当前必要工具消息。
5. 同名会话在不同账户隔离；同一账户不同会话隔离；持久历史重载后结论一致。
6. 新 run 与旧 chat 同一输入产生一致约束资料；取消、失败、删除及冻结快照保持原契约。
7. 学习偏好和当轮覆盖有明确提示，业务写入仍须提案确认。

更新固定基线，将 CF-28 从缺失行为刻画替换为目标能力检查，并增加修改/撤回场景；
记录基线版本和实际结果，保留旧报告。运行相关测试、完整后端离线回归、Ruff 和差异检查。
真实模型是否遵守输入约束仍需在线评审，离线请求检查不冒充回答质量达标。

预计实现涉及新增上下文模块、`agent.py`、专项测试、基线清单/说明与累计摘要。
前端、外部依赖和数据库 schema 不在首期变更范围。每次任务新增本地修改报告，
提交或推送继续以用户明确要求为准。

## 风险与后续

主要限制是受支持表达有限，以及模型看到约束并不保证一定遵守。
本轮用确定性识别和明确的资料边界验证可控闭环；不支持的表达不能包装成通用智能记忆。
后续若要求任意自然语言总结、日期作用域或跨会话事实管理，分别设计评测、额外模型预算、
用户可见的修改/删除入口和派生内容失效策略，再扩展同一接口。
