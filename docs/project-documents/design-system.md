# CampusFlow 设计契约 v1

本契约面向第十、十一阶段的 ArkUI-X 前端实施。核对基线为个人仓库 `3043f0c`（2026-10-18），以下“现有”描述均指这一版本；“新版”是待实施约定。第九阶段交付设计规范与交互原型，不代表客户端已改版、原生编译通过或设备验收完成。

产品定位是学生每日使用的校园任务助手：先看今天，再通过 Agent 形成可确认的计划，最后回到日程执行。保留现有数据与安全行为，在共享 ArkUI 页面内重组信息；Android/iOS/HarmonyOS 只在平台能力处适配，不独立复制三套 UI。界面采用克制的蓝白配色、清晰的时间与任务层级、紧凑的操作入口，避免营销横幅、大面积空卡片、装饰性指标和层层套卡。

## 1. 信息架构与路由

### 1.1 四个主入口

| 主入口 | 职责与第一屏 | 二级入口 | 边界 |
| --- | --- | --- | --- |
| 今日 | 下一节课/下一任务、今日课程与定时任务统一时间线、待安排事项 | 头像→个人；课程→课表当日；任务→计划对应任务；紧凑 Agent 入口 | 下一项按上海当前时间与真实数据计算；无日期/全天项单独呈现 |
| Agent | 当前会话、关联回答的任务提案、输入与语音 | 历史会话；次级菜单中的模型配置；相关能力快捷入口；头像→个人 | 快捷语句填入草稿，仍由用户发送；执行操作仍需确认 |
| 计划 | 冲突摘要前置；日程 / 目标计划 / 全部待办三视图 | 改期预览、计划展开、新增任务；日程中的周/月选择 | 三视图各有明确职责，完整目标→里程碑→任务和草稿均保留 |
| 校园 | 当前学校/校区/学期、课表入口、校园服务列表 | 课表维护；校园导航；教室/电费/图书馆/校园卡；能力管理；校园连接 | 依实际数据源展示可用性，未连接不显示虚构数据 |

“规划”在用户界面统一改为“计划”；内部 `Planning*` 类型和接口名称不必为文案重命名。“Skills”统一显示“能力管理”，主要入口在校园，Agent 可提供相关能力快捷入口。原 Skills 的安装、权限说明、启停功能必须保留。头像是个人入口，不再占据主 tab。

建议路由语义如下；这些是页面标识，不宣称已注册 URL 深链接：

| 页面标识 | 页面标题 | 常规来源 |
| --- | --- | --- |
| `today` / `agent` / `plan` / `campus` | 今日 / Agent / 计划 / 校园 | 四个主 tab |
| `profile` | 个人 | 主页面头像 |
| `account-settings` / `model-settings` / `app-settings` | 账号与校园 / 模型配置 / 应用设置 | 个人列表 |
| `history` / `history-detail` | 历史会话 / 会话标题 | Agent；未登录时另有只读离线入口 |
| `timetable` / `timetable-editor` / `timetable-preview` | 我的课表 / 编辑课程 / 导入预览 | 校园→课表；今日课程快捷入口 |
| `capabilities` | 能力管理 | 校园；Agent 相关能力快捷入口 |
| `campus-route` / `campus-services` / `campus-connection` | 校园导航 / 校园服务 / 校园连接 | 校园；保留今日现有快捷访问 |

### 1.2 返回栈与页面保留

1. 用明确的主 tab 标识与二级路由栈表达导航，不继续扩展 `activeTab > 4` 这种数字约定。每个主 tab 保留自身栈、列表滚动和已加载内容；切换 tab 不等于重建整页或提交表单。
2. 二级页隐藏主 tab 栏，显示返回按钮与标题。返回按钮、系统返回、支持时的返回手势走同一条退出逻辑。跨入口复用同一个页面：从 Agent 进入能力管理，返回 Agent；从今日进入校园导航，返回今日。返回来源放在栈帧中，不能只靠一个全局 `returnTab`。
3. 主 tab 根页再次点击当前 tab 默认不清空、不滚回顶部、不触发重复请求；根页系统返回遵循宿主退出行为，不额外造“返回今日”的隐式层级。二级页一次返回只弹出一层。
4. 成功进入 Agent 时，若已有未发送草稿，来自校园/计划的推荐语句先作为待采用内容显示，可“追加到草稿”或“保留原草稿”；替换需明确操作。不得由导航参数悄悄覆盖输入。
5. 表单有未提交编辑时，返回提供“继续编辑 / 放弃修改”，除非返回仅收起键盘。已提交但结果未知时，不能把“离开页面”等同于取消服务端操作；保留操作标识并提供状态核对。
6. 首次引导属于登录后的独立流程，没有主 tab；完成后进入今日。离线历史属于登录前只读流程，返回登录页，不创建在线会话、不恢复待执行提案。

### 1.3 状态所有权与清理底线

| 状态 | 切 tab / 二级往返 | 后台 / 退出账号 |
| --- | --- | --- |
| Agent 草稿、当前会话、待确认提案 | 同账号会话内保留；新一轮回复不能抹掉旧提案 | 后台停止音频；退出清空内存状态并隔离旧响应 |
| 语音识别 / 播报 | 离开 Agent 即暂停；已有转写保留为可编辑文字，返回不自动录音或播报 | 后台执行相同暂停；组件销毁释放引擎；账号切换清除文字与操作标识 |
| 计划浏览日期与月历月份 | 保留；浏览日期不自动改任务草稿日期 | 不作为账号无关的全局状态 |
| 新任务标题、日期、时间 | 折叠表单与切 tab 保留；成功保存后才按约定重置 | 退出清空；不将草稿伪装为已保存任务 |
| 计划 / 里程碑展开状态 | 按稳定 ID 保留；数据 revision 更新不重置全部展开 | 账号切换清除 |
| 页面滚动 / 历史选择 | 按页面实例保留；刷新优先保留可见项锚点，已删除则就近定位 | 不跨账号复用 |
| 课表编辑与导入候选 | 维护页内保留；候选确认后才替换草稿；旧预览响应失效 | 离页阻止旧响应写回；URL、PAT、Key 不进入路由或持久化草稿 |
| 提案确认 / 改期确认结果未知 | 保留 ID，只读核对；不能重发写操作或假称放弃成功 | 旧账号回调无权更新新账号；不从离线历史恢复执行按钮 |

本契约只要求同次登录内的路由状态保留，不新增“所有草稿重启后恢复”的承诺。已有本地历史白名单、账号范围、20 会话/约 2 MiB 限制、完整会话不截断、退出清理与删除墓碑语义继续生效。退出网络失败也不恢复登录；本地清理失败必须保留明确提示与重试入口。

## 2. 视觉基础

### 2.1 颜色与可读性

颜色全部通过共享主题语义引用。迁移期将 `bg/canvas`、`blue/actionBlue`、`secondary/quiet` 映射到同一新版语义，避免核心页与设置页继续使用两套蓝色。不要全仓盲目替换十六进制值；地图线条、状态和背景有不同用途，按组件逐项迁移。

| 语义 | 色值 | 用途 |
| --- | --- | --- |
| `canvas` | `#F5F7FA` | 页面背景 |
| `surface` | `#FFFFFF` | 内容组、底部栏、表单主体 |
| `ink` | `#182A43` | 标题、正文、关键时间 |
| `secondary` | `#526176` | 次级说明、元信息；不能再用低对比灰展示正文 |
| `accent` | `#2864D7` | 主操作、选中、可点击文字 |
| `accentSoft` | `#EAF0FC` | 次操作、选中底色 |
| `line` | `#DEE5EE` | 装饰性分隔线；不能单独承担输入边界或选中状态 |
| `controlOutline` | `#718198` | 需要明显边界的输入框、未选中控件 |
| `danger / dangerSoft` | `#B3261E / #FFF1F0` | 错误、删除确认 |
| `success / successSoft` | `#1E6B45 / #EAF5EE` | 有真实回执的成功、完成 |
| `warning / warningSoft` | `#875300 / #FFF4DC` | 时间冲突、结果待核对、服务能力受限 |

2026-10-18 按不透明 sRGB 实算：每通道先除以 255，`c <= 0.04045` 时线性值为 `c / 12.92`，否则为 `((c + 0.055) / 1.055)^2.4`；亮度为 `0.2126R + 0.7152G + 0.0722B`，对比度为 `(亮值 + 0.05) / (暗值 + 0.05)`。

| 前景 / 背景 | 对比度 |
| --- | ---: |
| ink / surface；ink / canvas | 14.47:1；13.48:1 |
| secondary / surface；secondary / canvas | 6.31:1；5.88:1 |
| accent / surface；accent / canvas | 5.39:1；5.02:1 |
| accent / accentSoft | 4.72:1 |
| danger / dangerSoft；success / successSoft；warning / warningSoft | 5.94:1；5.79:1；5.88:1 |
| controlOutline / surface；line / surface | 3.97:1；1.27:1 |

白字蓝底同样为 5.39:1。普通文字以至少 4.5:1 为设计目标；重要控件边界与状态不单靠浅色分隔线区分，使用清晰轮廓、图标和文字。[对比度依据](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。这些值只验证指定色对，透明叠加、禁用、按压和系统渲染需另验；不等于整应用通过无障碍认证。v1 交付完整浅色主题，暗色不得自动反色冒充已设计。

### 2.2 尺寸、字体与布局

ArkUI 布局长度使用 `vp`，字体使用随系统字号变化的 `fp`；网页原型以 CSS px 表达设计比例，不能证明原生 vp/fp、Android dp、iOS pt 的实机等效表现。[ArkUI 单位说明](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/reference/apis-arkui/arkui-ts/ts-pixel-units.md)。实施时检查具体属性的默认单位，文字明确使用 fp 语义，不用缩小字号解决溢出。

| 项目 | 新版规格 |
| --- | --- |
| 间距 | 主档为 12 / 16 / 20 / 24 vp；4 / 8 仅用于图标与文字、同一信息组内细节 |
| 页面内边距 | 手机默认 20 vp，窄可用宽度可降至 16 vp；区块间距 24 vp |
| 圆角 | 内容组 18 vp；按钮、输入、次级容器 12 vp；头像和状态圆点按自身语义处理 |
| 内容内边距 | 默认 16 vp；紧凑行上下 12 vp；无需每一行再套卡 |
| 字体 | 系统中文字体；主标题 28 fp/粗体，区块标题 20 fp/中粗，正文 16 fp，元信息 13 fp，tab 标签 12 fp；12 fp 不用于长说明 |
| 行高 | 正文约 1.5 倍字号，元信息约 1.4 倍；允许随字号增长，不能固定行高裁剪 |
| 图标 | 20 / 24 vp 两档，统一现有 AppIcon 线性语言；不使用 emoji 替代控件 |
| 操作尺寸 | 点击区域至少 48×48 vp；文字按钮使用最小高度而非固定高度，大字号下可增高 |
| 底部导航 | 内容基准 64 vp，叠加实际安全区；图标加文字、选中加形态或字重；不能依靠颜色单独区分 |

手机采用单列；正文标题、课程名、提案、错误提示完整换行，不使用整页横向滚动。代码、表格、地图可在明确的独立区域平移，并提供完整原文或列表替代入口。宽屏时正文列限制约 720 vp，计划可按可用宽度采用“日期列表 + 日程”双区；不得把手机卡片等比例放大。断点由可用宽度和实际内容决定，原型需检查 320 / 360 / 390 / 430 CSS px 及横屏，原生仍待对应设备验证。

底栏、输入区放在布局中占位，不覆盖末项内容；顶部和底部读取系统安全区。键盘出现后输入区仍可见，页面保留可滚动空间。大字体使并排按钮拥挤时改为纵向排列，不压成难读单行。月历七列在窄屏下若无法同时满足 48 vp 触区，使用可横向浏览的周选择或日期列表替代，不能通过声明“按钮 48”掩盖实际格子不足。

## 3. 共享组件契约

下列名称是职责约定，允许复用或拆分现有 Builder，不要求为每项新建文件。

| 组件职责 | 内容与规则 | 状态 |
| --- | --- | --- |
| 页面标题栏 | 主标题、可选副标题、头像或至多两个高频操作；二级页用返回替代头像 | 长标题换行；操作不挤压主标题 |
| 区块标题 | 标题 + 有准确口径的数量 + 可选“查看全部” | 加载中不先显示假 0；数量不足时不用占位指标 |
| 课程行 | 完整课程名，日期/起止时间，地点，教师；同组用细分隔线 | 空课表、当天无课、获取失败三种状态分开 |
| 任务行 | 完成控件、完整标题、时间和归属；详情展开显示地点/提醒参数 | 提交中锁定此操作；失败恢复真实状态；删除二次确认 |
| 计划摘要 | 目标、真实完成数、期限、展开按钮；展开后里程碑→任务 | 按 ID 展开；空里程碑与未归组任务显式展示 |
| Agent 提案 | “待你确认”及完整目标/任务/时间；确认与取消并列但主次清晰 | 确认中不重复提交；未知结果只有“核对结果” |
| 工具摘要 | 用户可理解的能力名称、执行状态、结果摘要 | 无记录标明未提供过程，不伪造步骤；不展示 raw arguments/result |
| 反馈条 | 图标、简短状态、原因与可执行下一步 | error / warning / success 用不同文本；不把所有消息都画成蓝色 |
| 表单字段 | 持久标签、输入、帮助、就近错误；必填可感知 | 不只靠 placeholder；保留粘贴、密码管理器、显示/隐藏密钥能力 |
| 能力行 | 名称、用途、已安装/启停状态；展开权限与版本 | 处理中禁重复；接口成功后更新；失败恢复并说明 |
| 空状态 | 一句事实 + 一句下一步 + 至多一个主操作 | 内容高度自适应，不设置大幅插画或半屏空卡 |
| 只读来源条 | 服务端最新 / 本机副本 / 尚未同步，已知时间与来源 | 本机记录不展示在线执行、取消或确认按钮 |

交互反馈采用轻微底色变化和系统按压反馈，不改变布局边界。短反馈约 100–160 ms、页面进入约 180–220 ms；沿用 `AppTheme.motion()` 尊重减少动态效果，不增加循环漂浮、自动轮播或等待期间的假进度百分比。图标控件有可访问名称，选中/展开/禁用状态可读出；装饰图标不重复朗读旁边文字。首个字段错误应可定位，确认与成功状态不只依赖一闪而过的 toast。

## 4. 三个核心页面

### 今日：接下来做什么，再看当天完整安排

新版顺序为：紧凑日期标题与头像 → 下一节课/下一任务摘要 → 今日统一时间线 → 待安排事项 → 一行 Agent 入口 → 进行中的计划摘要与校园快捷入口。统一时间线按时间合并当天课程和有明确时间的任务，用“课程 / 任务”文字标签区分类别，时间、标题、地点形成稳定层级；已完成任务降低强调并标明完成，不能继续用两张独立大卡把课程和任务分离。Agent 入口建议文案“把待办排进空闲时间”，不再出现大幅产品宣言。

“接下来”必须从 `Asia/Shanghai` 当前时间与服务端数据计算：课程日期和 HH:mm 按上海日历解释，带偏移的任务时间先转换到同一时区，再比较和显示。只在当日、起点尚未到达的有效课程与定时未完成任务中取最早项；并列项同时可见或说明有重叠，不靠任意排序掩盖冲突。若展示“正在进行”，必须有明确起止区间且满足起点 ≤ 当前时间 < 终点；没有结束时间的任务不能编造持续时长。页面进入前台、当前时间跨分钟/跨日时重算，跨日读取对应日期，离页停止界面计时。

未安排日期的任务与当前“全天”编码任务独立放入“待安排”区；全天项同时注明“今天 · 全天，未指定时段”，避免把已经指定日期误写为没有日期。这些项不参与下一项和时间轴时段计算。已完成、已取消的任务不进入下一项；历史已过时间项仍可在今日时间线查看真实状态。当前 `todayTasks()` 将今日与无日期任务合并后 `slice(0, 5)`，是本次要修正的现状：先分组，再分别计算准确数量，今日定时内容完整可达；待安排区可显示前几项，但必须写明“共 N 项”与“查看全部”。

单个数据源失败时，只对成功且日期有效的数据给出范围明确的提示，例如“下一节课”，同时说明“任务暂未更新”；不能把它称为全部安排中的下一项。缺时间、无新数据、当天无课与今日安排全部结束分别显示事实，不从缺数据推断“现在有空”。课程名和任务名充分换行；完成任务、删除计划继续使用现有接口与回执，删除计划不能宣称连同任务一起删除。活动计划保留详情入口与实际进度。

### Agent：会话是主体，提案是可操作结果

顶部为“Agent”、历史与次级菜单；模型选择/配置放在次级菜单，不与会话标题争夺首要位置。无会话时只显示一句能力说明与 2–3 个具体建议，建议点击后先填入草稿。已有会话时移除欢迎大卡。消息按角色与时间顺序排列，助手正文采用 16 fp 阅读尺寸；工具摘要在回答附近，默认紧凑可展开。提案与产生它的回答关联，在该回答下展示完整层级，不能只堆到对话末尾；详情可收起但不能截断任务或让旧轮次提案消失。已确认/取消提案留在原位置展示终态，若接口未返回关联字段，客户端以本次响应中的 proposal_id 记录关联，不按标题猜测。

输入区固定在可用区域底部并参与布局，包含多行输入、发送、语音；输入长度按既有 8000 Unicode 字符规则。等待回复时显示真实“正在处理”，不伪造思考过程；新草稿允许保留，失败恢复只在输入为空时进行，绝不覆盖用户刚写的文字。滚动位置已远离末尾时不强拉到底，提供“查看新回复”。

语音依次呈现准备、录音、整理、核对文字、播报状态，取消/停止始终可达；转写进入编辑区，用户再填入并发送。未支持的平台解释原因并继续文字输入。每条助手回答独立提供播报/停止，不能默认自动播放；切页与后台遵守状态清理表。模型配置缺失的操作应进入“模型配置”并原路返回草稿。

### 计划：日程 / 目标计划 / 全部待办三视图

标题与新增任务下方先呈现紧凑冲突摘要（存在冲突、未检查项或待核对结果时），详情可展开；随后是“日程 / 目标计划 / 全部待办”三视图切换。它们是同一计划页面的子视图，不占新的主 tab，不再把所有内容顺次堆成一条长页。各视图保留滚动位置，选中的子视图、日期与展开状态在切页后保留。

| 子视图 | 主体内容 | 操作与保留规则 |
| --- | --- | --- |
| 日程 | 周/日期选择、可展开的完整月历、所选日期的课程与定时任务；全天/无时段项分组 | 浏览日期与新增任务草稿日期分离；“安排这一天”进入 Agent 草稿；保留创建手动任务 |
| 目标计划 | 已确认目标摘要、真实进度与期限；展开后完整里程碑和任务 | 展开状态按 ID；空里程碑、未归组任务不能丢失；“规划这一周”作为紧凑 Agent 入口 |
| 全部待办 | 完整任务列表及明确的全部/待完成/已完成筛选，无日期项可独立定位 | 展示真实总数；完成、删除二次确认、加载/失败状态一致；不只呈现日程里有时间的任务 |

总体进度缩成目标计划视图的元信息，不占整张巨型数字卡。新增任务只维护一份草稿；切换三视图或收起表单不重置它。“规划这一周 / 安排今晚复习”不占据所有视图的巨大通栏区域。

日期浏览 `selectedDate` 与任务草稿 `draftTaskDate` 分离。今天/明天/日历/无日期只能有一个已应用选项；点日历中的日期不自动改尚未保存的任务。无日期清除具体时间；随后选具体时间按现有规则补今天；当前手动“全天”使用 `23:59:00+08:00` 且无 end_at，改视觉时不得悄悄改时区或存储值，也不能把它当成真实 23:59 时段参与自动排程。所有月份包含完整 6 行情形。

冲突区保留“仅自动调整有明确起止时间的未完成任务；其他待办仍需核对”。依次是核对结果→原任务与冲突课程→生成改期预览→旧/新时间与未能安排原因→确认/放弃。规则说明、未检查项、未解决项完整可分页访问；结果未知时只读核对，禁止重新生成或重复确认。改期成功再刷新今日与计划；不声称所有任务已无冲突。

| 历史列表与详情 | 标题、更新时间、内容摘要；打开后全文回看和来源条；删除入口收敛到明确操作 | 离线副本、尚未缓存、缓存失败、服务端不存在、删除结果不明；本地移除与服务端删除用不同文案 |
| 校园服务 | 教室、电费、图书馆、校园卡分段；查询条件收在所选服务顶部；结果列表替代重叠大卡 | 分类独立加载/失败；无权限与无结果区分；不把未取到的余额渲染成 0 |
| 校园导航 | 起终点与交换、生成路线、地图、完整路线摘要 | 地点获取失败、同点/无路线、地图未就绪；保留可阅读的路线信息，不只靠颜色 |

| 首次引导 | 三步：校园与学期→手动/导入课表→完整确认；进度明确 | 草稿与导入候选分离，警告一直保留到确认；地图校区不匹配或回执不完整不假成功 |

课表维护不能简单把首次引导重新打开并覆盖所有资料。当前 `completeOnboarding()` 会同时写学校、学期、整份课表和校园地图，且拒绝空课表；新维护入口需要明确读取当前资料与地图、维护草稿及保存边界。宜提取现有编辑/校验逻辑为复用单元，普通维护的保存或清空契约在实施阶段验证后接入，不假称现有接口支持删除最后一节后保存。后台订阅同步也不能悄悄覆盖维护页未保存的编辑：提示已有更新，让用户重新核对。

历史“继续对话”不是当前已完成能力。v1 不为离线记录添加可执行提案；如后续接入在线继续，应以服务端当前会话为准，验证归属、上下文与待处理状态，不能仅把缓存文本塞回当前会话冒充恢复成功。系统提醒同样尚未实现；当前提醒分钟数是保存参数，不显示“系统将在某时提醒”这样的完成承诺。

## 8. 分阶段采用与验收

第十阶段优先实施主题、共享标题/反馈/表单组件、四主 tab 路由与今日/Agent/计划。此阶段先保证现有个人、能力、服务与历史都能从新版导航到达；不以“新首页已完成”为由移除旧功能。第十一阶段完成校园首页、课表常驻维护、个人设置拆分及其余二级页，逐项核对刷新、返回与草稿行为。若维护保存需要后端接口调整，应作为明确子项交付，不在原型中假装已连接。

完成标准：

1. 四主 tab 与所有旧功能可达，二级多层返回准确；切页后草稿、日期、展开和滚动行为符合状态表。
2. 今日下一项使用上海当前时间与有效数据，统一时间线包含课程与定时任务、全天/无日期分开；计划三视图和前置冲突摘要可用。三核心页无大幅营销占位，长课程、长任务、长提案、无数据与错误均可读可操作。
3. 提案、课表和改期都先预览后确认；结果未知只核对；按钮多次点击不造成重复写入。
4. 课表更新后今日与计划刷新，未保存编辑不被后台刷新覆盖；已完成任务及 task/plan/milestone ID 语义保持。
5. 语音离页/后台停止，转写仍可核对；退出和换账号清理完整；历史离线入口不调用模型或执行提案。
6. 检查本文件色对与长文本、宽度、大字体、键盘、减少动态效果。HTML 原型验证仅说明网页原型；源码静态/模拟测试仅说明其覆盖逻辑。

本机不安装原生 SDK、模拟器或设备环境。本阶段不宣称 ArkTS 编译、三端安装启动、系统返回/键盘/读屏、沙箱重启、录音播报或系统通知已验收。后续文档与 PR 分列“源码已实现 / 静态或模拟验证 / 原生待验证”，由学长在已有环境补三端构建与设备证据。双端语音、系统提醒及历史继续对话不因视觉原型出现入口而自动成为已实现功能。
