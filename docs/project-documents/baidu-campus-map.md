# 百度校园地图接入与验收

校园导航页通过 ArkWeb 加载后端同源 `/static/baidu-map.html`，Web 对话路线卡片共用此页。
百度 JavaScript API 4.0 提供可拖动缩放的底图、起终点标记与道路折线；后端负责地点解析和真实路网步行规划，
页面和 Agent 使用同一算路入口。旧地图图片与人工 SVG 路线不再用于新路线，旧历史可保留文本摘要。

当前数据范围为杭州电子科技大学下沙校区。支持的账号别名为学校“杭州电子科技大学 / 杭电 / hdu”与校区
“下沙 / 下沙校区 / xiasha”，比较时忽略空白和大小写；不把其他学校或校区自动映射到此校园。
第一版只手选起终点，保留课程目的地预选，不请求 GPS 定位、不持续导航。

## 选择具体地点和入口

校园导航页可为起点和终点搜索百度候选地点，查看候选名称、地址和地图位置，再点击“确认此地点”。
候选搜索支持翻页和调整查询词。预览只改变地图视野，确认后才保存百度 UID 与 BD-09 坐标。
百度返回有效的校内导航引导点时，优先用该点预览和保存。候选没有可用引导点时，使用其校内 POI 坐标。
同一建筑的主体、南门、东门等候选由用户核对后选择，后续规划复用已确认入口。

当前候选凭证由单个后端进程签发，有效期为 10 分钟。重启后需重新检索待确认候选，
已确认入口保存在数据库中。多进程部署需统一候选签名密钥后再启用此流程。

选择按登录账号、校园数据包版本和地点 ID 保存。其他账号可以独立选择，包版本更新后需要重新确认。
修改入口后，新路线使用新入口计算。候选凭证短期有效，过期后重新检索；网络失败可重试。
Agent 读取当前账号的已确认入口，入口待确认时提示进入校园导航页操作。

Web 调试页在设置的学习数据区域提供校园地点确认面板。原生页面确认后会刷新当前地点信息，
保留已选起终点，并允许重新选择具体位置。

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/campus-data/places/{place_id}/candidates?page=0&query=...` | 登录后搜索当前校园的候选，每页 20 项，支持第 0 至 4 页 |
| `PUT /api/v1/campus-data/places/{place_id}/selection` | 使用搜索结果中的 `selection_token` 确认具体地点 |

地点名称按用户提供的清单更新，地点 ID 与原名称、常用简称的匹配继续有效。

## 个人配置与部署默认值

用户在百度地图开放平台分别创建浏览器端与服务端应用，开通 JSAPI 4.0、地点检索和步行路线所需服务。
在客户端的「个人设置 → 百度地图」或 Web 的个人配置中，可以分别保存浏览器端 AK 和服务端 AK。
留空表示保留该项现有配置，恢复服务默认值会清除当前账号对应的覆盖配置。两项配置都按账号加密保存。
部署的浏览器端与服务端 AK 也需使用不同的值。相同值的浏览器端默认配置会被禁用。
保存成功表示配置已写入；实际授权、白名单和额度需要通过打开底图、检索入口或规划步行路线验证。

维护者可以对照 `.env.example` 在 `agent-service/.env` 提供默认值。账号没有自定义的项目使用服务器默认配置。

```dotenv
BAIDU_MAP_BROWSER_AK=
BAIDU_MAP_SERVER_AK=
BAIDU_MAP_PLACE_OVERRIDES_JSON={}
BAIDU_MAP_REQUEST_TIMEOUT_SECONDS=5
BAIDU_MAP_TOTAL_TIMEOUT_SECONDS=15
```

修改部署环境变量后需重启后端。更新个人配置后，重新打开地图即可用新配置初始化 SDK。
空配置不阻止后端启动，地图或路线服务会明确提示不可用，
不改用人工路线。只填浏览器 AK 可显示底图，但不能完成服务端步行算路。

浏览器 AK 会提供给百度 JSAPI，需在百度控制台设置匹配实际页面来源的
Referer 白名单。联调时分别核对浏览器访问地址、模拟器实际加载地址、局域网地址及正式部署域名，
不要把一个地址可用误当作所有客户端都已获准。服务端 AK 只在后端向百度请求时使用，应限制服务器出口 IP；
开发电脑出口或部署出口变化后重新核对。AK 的应用类型、服务授权、额度和白名单均需在实际运行环境验证。

登录后，`GET /api/v1/me/baidu-maps` 与 `PUT /api/v1/me/baidu-maps` 仅返回两项配置的状态、来源和掩码。
登录后的地图运行配置 `GET /api/v1/me/baidu-maps/config` 仅含 `browser_ak`、`configured`、`route_configured`、
`campus_query`、`city`，响应禁止缓存。旧版公开同源配置接口继续提供部署默认值。
H5 桥接传递公开地图配置、路线和起终点数据；服务端 AK 仅供后端请求百度接口，登录令牌留在父应用。
SDK 来源固定为
`https://api.map.baidu.com/api?v=4.0&ak=...`。保留百度地图标识及版权信息。

服务部署在 `https://host/prefix` 等路径前缀下时，地图 CSS/JS 使用同目录相对路径，
公开配置从地图文档 URL 解析到同前缀 API，例如 `/prefix/static/baidu-map.html` 请求
`/prefix/api/v1/maps/baidu/config`。代理仍需将该前缀正确转发到后端。

## 查询预算与数据含义

| 环节 | 默认限制 | 含义 |
| --- | --- | --- |
| 后端单次百度请求 | 5 秒 | 不超过整次查询剩余时间 |
| 后端整次路线查询 | 15 秒 | 含算路和排队，候选搜索使用独立的有界查询预算 |
| 原生路线 HTTP 连接 / 读取 | 5 秒 / 20 秒 | 读取预算用于接收后端路线或安全失败回执 |
| 同地点对成功路线缓存 | 60 秒 | 按有效服务端凭据、包版本及确认入口复用，换密钥或入口后重新算路 |
| H5 配置 / SDK / 校园检索 | 6 秒 / 12 秒 / 6 秒 | 页面有独立加载预算和明确重试，不后台无限重试 |

路线坐标使用百度 BD-09 经纬度（`coordinate_system=bd09ll`），折线点为 `{lat,lng}`。
返回的 `distance_meters`、`duration_seconds` 及向上取整的分钟数来自百度步行规划，
`is_estimate=true` 表示预计耗时，`queried_at` 标明查询时间。60 秒缓存与百度上游数据都不代表实时路况；
门禁、封路、施工、校内通行、无障碍入口及开放时间仍以现场信息为准。

未配置、上游超时/错误、无路线、地点无法确定或存在歧义时分别失败并提供可重试提示，
不返回旧人工图路径，不伪造经纬度，不把任意首个同名 POI 当作校园或入口。
初始校园检索按校园名和城市筛选后判断唯一性。建筑入口通过候选列表人工确认，
模糊检索总数超过一页时仍可查看本页合法候选并翻页。

## 校准地点入口

17 个地点 ID 沿用项目数据包，名称根据用户提供的 `列表.md` 更新，入口需要在候选列表中确认。
实际 AK 验收时核对百度返回的杭州市、下沙校区、名称、入口位置和 UID；同名、多个入口或多校区结果必须人工确认。
维护者也可用 `BAIDU_MAP_PLACE_OVERRIDES_JSON` 按既有 `place_id` 提供明确入口。
用户在页面中确认的入口优先使用，部署配置作为已有入口的来源。

该配置为一个 JSON 对象：键是下表中的地点 ID，值只能包含以下字段：

| 字段 | 类型与要求 |
| --- | --- |
| `lat` | 必填，已核验的 BD-09 纬度数值，有限数，范围 -90 到 90 |
| `lng` | 必填，已核验的 BD-09 经度数值，有限数，范围 -180 到 180 |
| `baidu_uid` | 可选，百度对应 POI 的非空 UID 字符串 |

下面仅展示结构，尖括号内容必须替换；`lat` / `lng` 最终须为 JSON 数值，不能保留示例字符串。
不提供未经核验的坐标样例，空对象 `{}` 可直接作为默认配置。

```json
{
  "library": {
    "lat": "<已核验的百度BD-09纬度数值>",
    "lng": "<已核验的百度BD-09经度数值>",
    "baidu_uid": "<可选的已核验百度UID；不用时删除此字段>"
  }
}
```

将核验完成的对象压缩为单行 JSON 后放入本地环境变量，保存并重启后端。
不要使用图片 x/y、WGS-84 GPS 或 GCJ-02 坐标冒充 BD-09，也不要交换 lat/lng。
配置错误会使路线服务不可用，不能仅通过关闭校验恢复。

## 停用与逐文件回退

维护者可清空部署默认 AK 并重启后端。账号仍可使用已保存的个人 AK；如需停用某个账号的地图，
在个人设置中将两项都恢复为服务默认值。账号、课程和历史资料会保留。

需要恢复本次代码修改前状态时，使用**本次本地修改日志中的逐文件回退包**及对应说明，
逐项核对修改前文件、新增文件和用户后续修改。仅回退本次地图相关文件，不对整个仓库执行 reset/clean，
不覆盖用户原有文档、演示视频、凭据或运行数据库。回退后重新执行日志指定的相关验证，再决定是否重新构建客户端。
