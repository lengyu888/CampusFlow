# CampusFlow 第九至十六阶段

本轮以第八阶段 `6c514b0` 的功能为基础，个人仓库初始集成提交为 `3043f0c`。按 2026-10-18 用户最新授权连续完成第九至十六阶段，第十七阶段暂不开展，不进行真实模型付费评测。每阶段完成适用检查后上传个人与原项目的独立分支，再进入下一阶段。所有原作者署名及历史保留，两个仓库的 `main` 均不直接修改，不强推、不自动合并。

## 验收口径

以用户确认的赛事截图为准：ArkUI-X 一套核心 UI 与业务代码，鸿蒙、Android、iOS 三端均须支持文本多轮对话和本地历史回看；鸿蒙 ASR → 云端 Agent → TTS 必做。双端语音、记忆/知识、模型适配和工程质量属于增强项。工具反馈必须来自真实执行事件，知识结论必须有依据，所有实际变更必须经过显式确认。

不安装原生 SDK、模拟器或设备工具，不做实机验证。源码、静态检查、模拟能力测试、浏览器设计原型、后端集成与原生编译/设备证据分别记录；不将前者描述为后三端已跑通。缺原生环境时构建和签名也标为待验证。真实模型测试仅使用已授权凭据与预算；配置、密钥、个人数据不提交仓库。

## 每阶段证据

每阶段说明文件记录：基线、变更、具体使用价值、实际执行检查、未执行项及双仓分支。PR 以本轮上一阶段分支为基线，便于只看当期增量。第一阶段个人 PR 以个人 `main` 为基线，原项目 PR 以 `feat/timetable-conflict-replanning` 为基线。原项目专用副本仅接收本轮功能提交，不带入个人仓库的维护人和协作配置。

客户端沿用现有 Node 逻辑/契约检查及静态工程检查；服务端沿用 Python 离线测试，并按实际风险补并发、回滚、权限、恢复和集成用例。设计预览进行浏览器交互与视觉检查。检查失败先修复，不靠减少验收范围或删掉有意义的测试宣布完成。

后续状态以对应提交、PR、阶段说明和实际检查日志为准。本文件是范围契约，不表示九至十六阶段已经完成。
