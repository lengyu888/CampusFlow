# 第十二阶段：计划执行可靠性

基线：个人仓库 `f2f1986`、原项目 `b8cab4d`。独立分支 `feat/stage-12-reliable-planning`，分别以第十一阶段分支为 PR 基线，两个 `main` 不修改。

## 具体作用

创建、编辑、删除任务或计划都经过同一套预览、明确确认和结果回执。预览展示原值、将修改的值、冲突与未核验项；过期或数据已变化时说明原因并重新预览。删除计划保留子任务为独立待办，并在确认前说明。

确认前重新检查当前课表、已有任务、计划期限和候选内部的时间重叠；未填写完整时段不显示“无冲突”。历史任务的时间可以修正，已完成任务可先改期再恢复为未完成，恢复也检查最新冲突。

同一提案重复确认只返回原回执。一次提交的任务、计划、里程碑及回执在一个 SQLite 事务中落库，中间失败全部回滚。账号隔离、准确 ID 定位、候选内容和原始快照检查覆盖创建、修改和删除。

## 客户端与 Agent

- 计划页原有草稿、滚动和详情导航保留，创建/编辑/删除接入统一确认面板；普通变更与课表重新规划在该页互锁。
- Agent 工具可提议修改或删除准确 ID 的事项，不能执行确认；仅查询时不生成写入提案。权限说明明确每笔变更均须用户确认。
- 网络超时先查原提案，成功回执才显示已完成；只有可靠查回待确认状态后才能重试同一提案。服务已判定过期/失效的提案不会因多次点击重新变为可确认。
- 旧版本未携带可靠合同的提案要求重新预览；回执详情链接来自服务端准确 ID，不按标题猜测。

## 合同与证据

`POST /api/v1/planning/actions` 返回 `contract_version: 2` 提案，含有效期、目标 ID、原值和警告。`POST /api/v1/actions/{id}/confirm` 将结果及同一回执一起返回，重复请求读取已存回执；`GET` 可查结果，`cancel` 可显式取消仍待确认的旧预览。

后端完整离线回归 323 项通过、2 项真实模型用例按已有标记排除，其中 ActionService 新用例 38 项。客户端完整回归 406 项通过，静态检查 44 个 ArkTS/TS 文件及 17 个配置文件通过。真实 FastAPI HTTP / SQLite 生成的 14 份创建、编辑、删除、取消及回执投影由生产客户端验证器接受；重复确认回执一致，删除计划后子任务保留。相关 Python Ruff、ArkUI-X 静态检查和 `git diff --check` 通过。

客户端未知结果在当前页面实例保留；不声称已跨进程持久化，或所有页面使用全局写锁。旧直连任务 POST 保留兼容，但没有客户端操作 ID，不能自动重发未知结果。新版页面使用提案 ID 去重。未安装原生环境，未做三端编译、实机、原生 UI 渲染或真实模型调用。
