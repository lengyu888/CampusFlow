# UX07：连续录课、逐行导入和清楚的设置入口

## 具体有什么用

首次引导和课表维护共用录课编辑器：规范手动输入与日期、时间选择并存，字段错误就在输入旁边，提交失败保留原内容并定位首错。可以“加入并继续”连续录下一门，也能明确选择沿用上一门的信息；复制只是新草稿，仍需核对日期、周次、课程名和地点，不会自动再加一门。

导入先展示每一条源事件，再按新增、六字段完全重复、时间重叠、无效内容分类。可以查看完整字段、修改或明确排除；重叠需核对双方课程，改了课程或当前草稿后旧确认失效。同名课程不会被推断成同一门的修改。按钮的作用是把选中课程加入本地草稿，最后仍需确认整个课表，并通过原版本和操作回执保护保存。

校园首页先展示我的课表、路线和校园服务，天气缩为摘要；资料查询点击展开，收起后保留当前问题。示例来自已收录的官方资料范围，点击只填问题，不自动查询。已有输入会先让用户选择是否替换。

个人设置按账号与校园、学习偏好、模型连接、语音与提醒、历史与数据组织。账号下面再进入校园数据连接。返回先退一层，保留尚未保存的表单；学习偏好控制器保持挂载，不因为换页面丢掉待核对操作。清除草稿和退出放在历史与数据里，与常用保存分开。

## 导入数据如何被处理

预览接口增加版本化行诊断，保留源事件序号、完整六字段、原时间信息和具体原因。长字段不会先截短再假装合法，重复课程也不会在预览之前悄悄消失。UTC 时间正确换算为校园北京时间；源日历未提供时区时明确告知解释政策。当前课表无法表示的跨日课程、重复系列及其他不支持情况逐条说明，不假装已经完整展开。

全部源事件可用时，旧客户端仍得到合法的兼容列表；混合坏行时该列表为空，新客户端从完整诊断行核对，避免旧客户端把部分数据当成整批成功。事件超出 500 条或无法可靠划分结构时整次拒绝，不只保留前一部分。

订阅绑定和同步也先检查完整性。需要逐条核对的订阅不会替换现有课表；用户到维护页预览处理。有效订阅仍保留原版本检查。接口错误只显示受控说明，不把订阅地址或令牌带进提示。

源行编号只在这次预览内有效，不是永久课程编号。没有自动按名称覆盖旧课。未加入课表草稿的行级预览需要重新取得诊断后核对；订阅地址不进入本机草稿。

## 信息与输入边界

资料详情分别写清整理核对日期、未提供的原文发布日期以及非实时性质。未支持校区、未命中和请求失败仍分别说明，未连接个人校园数据不隐藏常用入口。

账号表单显示是否有未保存修改。模型保存不会发送另一组账号草稿，保存回包也不会清掉等待期间新填的密钥。未知写入结果保留原输入，先核对已保存状态再决定下一步。
