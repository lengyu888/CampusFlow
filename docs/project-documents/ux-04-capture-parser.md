# UX04：快速语句与课程路线

本说明覆盖确定性解析器、课程地点匹配和路线页接线。首页来源与空档、快速表单、课内任务许可由本阶段其他模块整合；这里不把纯函数或网页预览称为原生验收。

## 快速语句只生成候选

`QuickCaptureParser.ets` 导出 `parseQuickCapture(text, anchorDate)`。原文逐字保留，基准日期由草稿提供，校园时区固定 `Asia/Shanghai`；重新打开草稿不会自行按新一天重算“明天”。返回可编辑标题、具体日期、开始时刻、分钟数，以及安全的 `issues` 和 `unsupported` 说明。没有网络、模型、写入或自动确认。

| 支持输入 | 结果与边界 |
| --- | --- |
| 今天、明天、后天、真实 `YYYY-MM-DD` | 具体日期；非法日期不自动进位 |
| 周五、星期五 | 从基准日起最近一次，含当天；完整日期须显示供核对 |
| 本周、下周 | 周一作为一周起点；本周已过去的日期保留并提示 |
| `20:00`、上午九点半、下午三点十五分 | 明确时刻；时段与数字时刻冲突时留空并提示 |
| 明晚八点复习一小时 | 基准日 +1、20:00、60 分钟、标题“复习” |
| 周五下午交报告 | 可确定日期；开始时间空，不能猜 15:00 |
| 25 分钟、一小时、半小时、1.5 小时 | 正整数分钟，1–1440 分钟；多段时长先让用户合并 |
| 交报告 | 无日期待办候选，允许用户主动按无日期保存 |

首版不解析循环规则、节假日、下课后、有空时、粗略“八九点”、一句多项，以及多个竞争日期/时刻。裸“一至十二点”缺少上午/晚上也需核对；不按标题、课程或地点猜时间。未支持说明同时进入表单使用的 `issues`，不会被只显示字段错误的页面漏掉。

解析只移除确定识别的片段，不截断原文或长标题。日期、时刻或时长缺失时仍可留作草稿；标题提交上限由共同任务契约保持 120 个 Unicode 字符。用户始终能逐项修改，再进入服务器完整预览与显式确认。

`captureEndAt(date,time,durationMinutes)` 仅在日期/时刻/分钟数完整有效时计算结束时间，跨日结果保留完整日期和 `+08:00`。超出可用年份返回 null，页面须阻止该候选，不能当作未填时长保存。

现有手动全天记录使用 `23:59 + end=null`。因此明确输入 23:59 但未提供时长会返回 `TIME_PRECISION_REQUIRED`，要求补时长或主动选择全天，绝不静默混成全天事项。

## 课程地点不等于定位

`CourseRouteIntent.ets` 的导航对象保留：请求代次、学校、校区、课程六字段、课表 revision 和整份课表 evidence。课程没有稳定 course_id；不以同名课程的第一项、索引或标题充当身份。来源说明不虚构每一课的原始导入出处。

地点匹配使用当前数据包真实 `name/aliases/place_id`，先核对学校与校区，再识别完整名称或有明确数字边界的教室后缀。例如“第7教研楼北406”只能匹配到楼宇，北406仍按原文展示；不会生成教室坐标。7 教不能匹配为 17 教；多义、未知、异校区都不自动选择第一项。多义列出真实候选，用户可明确选择。

路线页接收 `courseIntent`、`routeScope`、`routeContextKey`。scope 来自服务地址与账号身份，不依赖历史文件是否可用；切换账号清空路线、课程来源和每个根页面的手选缓存。按根导航保留选择，隐藏/返回不会重置当前起终点；父页面的 context 与 intent 变化合并后应用，避免短暂串到另一根页面。

新入口没有默认当前位置。唯一课程匹配只预选终点；起点必须用户手选。路线请求发送准确 place_id，收到结果还需匹配本次起终点及地图包版本；选择变化、来源失败、换账号、隐藏或销毁后的旧回包不能恢复旧路线。地图继续明确为示意路线和步行估算，保留来源；不含实时定位、临时封路或实际送达保证。
