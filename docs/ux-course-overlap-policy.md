# 课内任务：允许设置，保留提醒与确认

2026-10-18 用户补充：有些安排可以在上课时完成，因此应允许设置，同时提醒。此条更新本轮UX任务书的重叠规则；不再把所有课程/任务重叠一律当成必须改期。UX01展示交互，UX04–UX06落实字段、接口、排程及变更提示；本文件不是后端已实现证明。

## 用户看到的行为

1. 每条任务提供“可在上课时完成”，默认关闭。不是全局“忽略所有冲突”。
2. 开启后仍计算并展示具体课程、完整日期、重叠区间以及待办内容。用户可选“换个时间”或“仍这样安排”。关闭面板或取消不会保存新许可。
3. 只有明确确认后，任务显示“已确认课内安排”。重叠事实继续在详情可见，不显示“没有冲突”。
4. 助手只对用户明确允许的任务考虑课内时段；普通任务仍避开课程，用户未设置时模型不得自行放宽规则。
5. 课表变更出现新的课程重叠，或任务时段/内容/许可改变时，重新核对并展示相应提醒。不能沿用一个永久“忽略”标记。
6. 无法读取课表时不能显示“已确认课内安排”；恢复后先核对。未知保存结果按原操作ID查证，不重复创建。

## 实施契约（UX04–UX06按当前代码冻结具体字段）

- 任务级布尔许可默认false，旧数据升级后仍默认false。设置许可不等于确认某次具体重叠。
- 提案的结构化警告包含实际任务、课程快照或完整课程字段、校园时区和重叠区间；确认时对准确提案内容及最新课表复核。
- 记录可核验的明确确认，与提案内容、任务版本、重叠课程及课表快照关联，和业务写入/回执原子保存。客户端提示、模型文本、通用草稿不能代替服务器确认。
- 旧确认接口不携带必要确认信息时，含新课程重叠的写入依然拒绝；兼容不能成为绕过入口。
- 只放行被允许并明确确认的**课程—任务**重叠；任务—任务、任务自身非法区间、截止日期、身份、版本、提案有效期和事务保护不放宽。课表内课程—课程重叠仍按现有规则处理。
- 不同校区同名课不混淆；当前课程无稳定ID时使用完整字段及快照，不能只按标题或数组下标识别已确认范围。
- 自动改期不悄悄消除用户接受的课内安排；新增/变化的重叠仍进入待核对列表。更新已有安排不能复制任务或篡改原ID。
- 已有任务允许撤回课内许可；若仅撤回许可且其他字段不变，可保留原任务并明确显示待调整冲突，不能因为已有重叠而使开关永远关不掉。撤回不等于消除重叠。
- 未保存的计划子项由服务端提供候选标识，不能按标题或数组位置授予许可。课表当前内容摘要不是单调版本号，不声称它单独防住内容往返变化。
- 恢复未完成（UX08）仍使用同一核对规则，不能绕过失效的课程确认。

## 必需检查

默认普通任务拒绝课程重叠；开启但未确认不提交；正确确认只放行准确课程交集；拒绝泛化到任务互撞；取消保留旧状态；同名/跨日/多课重叠；课表变更或另一端编辑导致确认过期；重放幂等；关闭许可的已重叠任务要求先调整或明确保留待处理状态，不悄悄宣称无冲突。页面文案、模型工具、手动创建、编辑、课表变更扫描和规则改期必须一致。
