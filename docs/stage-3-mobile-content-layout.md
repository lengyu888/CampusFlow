# 第三阶段：长内容、输入区与地图适配

本阶段接续第二阶段提交 `4e34ae5b237851bd4985676936efc68a9609ee96`，保留现有主题、接口及计划确认流程。目的是让手机上较长的回答、课程和输入更容易阅读，修正固定地图宽度及日期重复高亮问题。

## 可见变化

- Agent 与历史详情共用消息组件：段落、标题、列表、围栏代码分开排版；简单表格转换为逐行卡片，每格带列名，避免横向挤压。
- 代码保留缩进，长标识符和 URL 可以换行；格式化回答可切换到完整原文并长按复制。未支持的语法保持文本，不执行 HTML、远程图片或回答中的链接。
- 助手回答使用完整内容宽度；规划中的课程地点、任务时间和说明允许换行，移除相关固定行高。历史详情显示完整会话标题，列表仍保留摘要。
- 输入区按内容增高，并根据页面可用高度设置上限；入口设置键盘避让为 `RESIZE`。超过接口的 8000 字符上限时提示精简，原输入保留，不静默截断。字符计数按 Unicode 码点，与后端长度约束对应。
- 规划页日期、时间选项改为两列，长按钮文字可换行。“今天”和日历恰好选中同一天时，只突出本次使用的入口；浏览月历不会改写待办草稿日期。
- 校园地图从固定 330 宽改为容器宽度；底图、路线、站点与线宽使用同一比例，画布尺寸变化后重绘。

地图保留已有坐标校准、裁切区域和道路数据，本阶段没有重新测绘路线。原有减少动效设置保留，没有新增动效。

```sh
node --test scripts/test-*.mjs
npm run check
```

- 测试覆盖畸形表格不丢单元格、长文本、代码围栏边界、含下划线的 URL/标识符、不同宽度共享坐标比例、日期单选，以及 8000/8001 个 Unicode 字符输入边界。
- 静态检查 **27 个 ArkTS/TS 文件、17 个配置文件通过**；`git diff --check` 通过。
- 交叉复核修正了键盘枚举缺少导入、行内代码/下划线误处理和代码围栏误识别。
- 本阶段没有修改后端；沿用第二阶段的接口，未重复运行后端测试。

上述 Node 测试执行提取的实际逻辑或工具函数；静态检查检查工程结构及源码规则。它们不等同于 ArkTS 编译、原生排版或键盘测试。

当前机器没有匹配的 DevEco/ArkUI-X SDK、Java、Android 构建环境及完整 Xcode。未运行原生构建、模拟器或真机测试，没有生成本阶段实机截图；本阶段以 **Draft PR** 交付。

| 场景 | 预期表现 |

| 窄屏与横屏 | 在约 320/375 vp 及横屏下阅读长课程名、地点、任务说明，正文不被按钮和固定列挤出；可滚动到全部内容 |
| 系统大字体 | 标题、时间与按钮可读，触控目标可用；安全区和底部导航不遮住最后一行 |
