# 行简｜比赛演示脚本

讲述主线：**课表提供约束，助手提出候选，用户确认后执行；课表改变时再核对，执行与回看都有依据。** 重点展示一个目标怎样落到具体任务，少翻功能目录。

源码基线为 UX11 `fce0e1d2f46329d1d3552924be890ca0653866d3`。对应要求及三端设备验收见[赛事交接表](ux-12-competition-acceptance.md)。本轮已有的是源码、离线逻辑与浏览器近似证据；下面设备演示步骤须由学长在已有环境完成，**尚不能说三端运行、真实云对话或语音链路已经验收**。

## 先选清楚演示方式

| 方式 | 用途与入口 | 开场必须说清 |
|---|---|---|
| 离线设计展示 | 优先打开[最终演示入口](previews/ux12-final-demo.html)；单章备用为[UX11 交互原型](previews/ux11-experience-polish.html)、[助手](previews/ux-05-assistant.html)、[计划](previews/ux-06-planning.html)、[录课](previews/ux-07-campus-forms.html) | “这是合成数据的浏览器交互近似，展示实际页面方法与设计，不是原生运行，也没有调用真实模型。” |
| 离线连续逻辑复现 | 已有 Node／后端测试依赖时运行下方 `test:journey`；查看[14步旅程记录](evidence/ux-11-journey.json) | “实际客户端逻辑通过本地接口访问真实 SQLite；模型流、订阅传输和时钟是测试替身。编号与业务回执由真实服务生成。” |
| 比赛现场设备演示 | 学长先按[设备表](ux-12-competition-acceptance.md)完成对应平台构建、联网与权限验收，再按下文操作 | 展示平台、当前代码版本和已验证范围。未通过的环节切到已标注的离线材料，不能把替身说成现场真实能力 |

离线复现命令（在仓库根目录，复用已有环境，不自动安装）：

```sh
cd arkui-x-client
CAMPUSFLOW_TEST_PYTHON=/已有环境/bin/python \
  CAMPUSFLOW_JOURNEY_REPORT=/临时输出目录/ux11-journey.json \
  npm run test:journey
```

路径需替换为队友实际环境。脚本使用临时文件和同进程 ASGI，不开端口、不连接模型／校园账户；缺依赖应明确报告。输出通过不代表原生编译通过。当前参考旅程已验证提案确认丢响应后的原 ID 恢复、草稿新版本保留、70秒已同步时段、离线尾段缺口和账号隔离；这些是合成案例，不是使用效果或性能统计。

## 设备演示前准备

1. 选专门的演示账号，注册时可不填模型 Key；选已提供公共参考资料的“杭州电子科技大学／下沙校区”。首次配置只需一门课程，模型稍后在“个人设置”配置。
2. 设备使用能访问的现有后端地址；由队友配置一种实际可用模型。模型列表的“可用”只说明配置门禁通过。不要在录屏中展开 Key、订阅 token 或请求认证头。
3. 设 `D` 为演示时北京时间的**明天**，避免候选已经开始或跨日理解不一致。录入 `D 08:00–09:00`“合成高等数学”，地点“合成教室101”。所有演示页使用同一账号与同一日期。
4. 在“能力管理”查看权限并安装／启用“课表规划师”和“DDL 守望者”。新账号不会自动获得写提案工具；遗漏这一步时模型可能只能查询，不能把没有候选归咎于界面。
5. 清楚区分两种课表操作：首次／课表维护“导入预览”只导入本次确认结果；个人设置的“连接新课表”会绑定后续同步。本脚本主路径用手录，避免临时订阅授权阻塞。固定合成 ICS 只用于离线旅程，不把其 URL 当真实订阅发到线上。

## 主演示：一件事从安排到回看

建议主线约8–10分钟，真实模型等待时间按现场情况调整。引号中的话可直接口述；按钮以当前版本可见文字为准。

| 顺序 | 操作 | 画面中应核对什么／可说的话 |
|---|---|---|
| 1. 从真实约束开始 | 新账号选择校园与学期；“手动录入”添加准备的一门合成课程；进入“核对完整课表”，点“确认课表并开始使用” | 先展示完整日期、起止、地点，再保存。“模型不是凭空安排：先有我确认的课表，尚未确认的输入只是草稿。” |
| 2. 快速记下一件事 | 在“今日”的快速记录输入“明天晚上八点复习一小时”，核对 `D 20:00–21:00`；存在歧义时手工选择日期／时长；预览后确认 | 这是确定性解析与人工核对，不宣称本步骤调用云模型。计划中应只新增一次这项任务，先不完成 |
| 3. 让助手推进目标 | 在“助手”发送：“请先查看我 **D** 的课程和已有任务，安排 **D 19:00到20:00** 复习操作系统，地点图书馆，提前10分钟提醒。先给我候选，不直接执行。”把 D 换成完整日期 | 实际可见工具进度、数据来源及候选。模型若追问或生成错误时段，正常补充／重新生成并核对；不要预告它必定采用某个固定工具序列 |
| 4. 多轮与确认 | 在同一会话补充目标细节。最终核对任务标题、日期、地点、提醒、冲突和来源；只确认一份准确候选，其余不用的候选取消 | “这张卡片是待确认安排，回答本身不会写入任务。”确认后打开对应任务与回执，验证不是按同名标题找到另一个任务。第二轮若另生成了候选，应明确处理旧候选，避免两份都确认 |
| 5. 制造一个真实变化 | 从“校园”进入“课表维护”，新增 `D 19:00–19:45`“合成晚间课程”；核对整份课表并保存。到“计划”的“课表与任务核对”展开详情 | 应指出准确任务与课程、地点及交集。未设完整时段项会另列待核对，不能把它们说成空闲 |
| 6. 再确认改期 | 生成规则改期预览，先看原时间／新时间，再点“确认调整这…项任务”。本例另有20–21点任务，可用时段预期为21–22点；以实时预览为准 | 预览期间任务时间未改；确认后 ID 与时长保留，不提前于原安排，不撞课程／其他任务。“已许可课内任务会保持原时段，需要复核的许可另行处理。”本例默认不允许课内完成 |
| 7. 鸿蒙语音必做环节 | 点“语音输入”→说明与权限→说“请概括刚才确认的复习安排”→“完成录音”；修改识别文字，点“填入输入框”，再手动发送。真实回答后点“播报”，再点“停止” | 显示 ASR 草稿、用户发送、真实模型答复、设备 TTS 四段。“录音不由应用保存，系统识别可能联网；识别不会自动发送。”三端文本均须验，Android／iOS语音是额外展示 |
| 8. 重启回看 | 先在线打开会话使其缓存，关闭应用；断网重开，从登录页离线历史入口查看。恢复网络后重新登录，打开历史并明确选择续聊 | 缓存应保留文字；历史提案只读，续聊前核对服务端上下文。**此处不点退出账号**，因为退出会清除本机历史与草稿；重启也不会恢复登录令牌 |
| 9. 做一小段专注 | 从具体待办进入专注，开始、暂停、继续、结束；展示本机核实时长与已同步片段。设备负责人已验证可靠时钟后才演示 | “计时结束不等于任务完成。”若需要，另外点“标记这项任务已完成”，等状态回执；普通完成留在当前页面，恢复未完成另走预览与确认 |
| 10. 回看有依据的事实 | 从“今日”点“回看这一天”，选择**实际计时与完成发生的今天**，不是任务原计划的 D；打开完成与专注依据。可填写一句私人感受，预览交给助手的摘要 | 只统计已确认片段和有效完成事实，不把缺口、未同步数据或“没有记录”解读为学习效果。私人感受默认不进入摘要；“放入助手输入框”只转成草稿，已有文字保留，不自动发送 |

结束口述：“行简把目标、课表、人工确认和执行记录连起来。我们能解释安排依据，也能在变化或失败时核对结果；现场已验证的平台和未验部分分别记录。”

## 可选补充与失败处理

| 情况 | 当场怎么做 | 不应做什么 |
|---|---|---|
| 要展示订阅导入 | 使用获授权的真实订阅，在“读取预览，不保存”后逐条看新增、重复、重叠及无效来源；修正或显式排除，再核对最终整表 | 不显示链接 token；不把坏行默默丢弃，不声称确认时会重新抓一份数据 |
| 想演示可在课内完成 | 在手动预览里明确开启该任务许可，展示完整课程和实际重叠，再逐项确认；修改课程后重新核对 | 模型不能自主授予；课程许可不能豁免任务间冲突和截止限制 |
| 确认请求超时或断网 | 保留“待核对”，先用原操作标识查询回执；服务明确允许时才由用户重试同一笔 | 不重复新建候选，不把网络报错说成一定没写入。可播放[离线旅程](evidence/ux-11-journey.json)对应故障证据，明确是注入故障 |
| 另一端已改课表／候选过期 | 显示冲突或过期原因，保留当前草稿，读取最新状态后重新预览 | 不强制覆盖服务端新版本，不照旧确认15分钟前的候选 |
| 语音权限拒绝／服务不可用 | 展示真实提示，保留文字输入；在验收表记录平台条件。可用录制的真实设备验收片段补充，并标注录制版本 | 不播放合成音频冒充本次设备识别；不把浏览器按钮动画说成 ASR／TTS 已通过 |
| 模型未配置／供应商异常 | 打开配置提示，继续展示手录、快速记录、规则改期、专注和回看；真模型环节记未完成 | 不把脚本替身包装成真实对话，不换用来源不明凭据 |
| 本机保存失败／专注进程中断 | 保留当前输入或待同步记录，先恢复存储；展示仅保留已持久片段、未知尾段不补算 | 不为了顺畅演示清掉未知操作或猜测计时时长 |

通知加分可在主线外用一个近期任务单独演示：“个人设置”明确授权后检查系统受理、实际送达、改期与退出清理。系统受理不是送达保证，不把通知等待时间塞进主线。

## 最少留下的比赛证据

- 三端分别保存同版本安装／冷启动、两轮真实文本对话、断网重启回看；鸿蒙另保存一次完整 ASR→手动发送→真实 Agent→TTS 连续录像。
- 主线保存候选未确认、确认回执、课表变更、改期结果四个节点；再留专注片段与回看来源，允许展开技术编号核对，但日常叙述优先任务名称。
- 录像标明平台、日期、源码 SHA 和是否联网；只用合成账号资料，遮蔽凭据。浏览器近似、脚本替身与实际设备材料分别命名。
- 将实际结果补入[设备验收表](ux-12-competition-acceptance.md)；没有完成的项保留“未执行”及续做条件，不用“功能完善”笼统替代。

本脚本不启动部署、真实模型对比评测或旧第十七阶段工程任务，也不要求用户本机下载原生环境。
