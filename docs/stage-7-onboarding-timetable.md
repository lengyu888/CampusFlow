## 有什么用

新用户没有课表订阅链接，也能手动添加真实课程后进入应用。首次配置按「确认校园和学期 → 添加课程 → 核对并保存」推进；导入先给预览，允许加入草稿后逐条修改，最后才保存核对过的课表，供既有 Agent 查询和规划使用。

- **手动录入**：课程名、具体上课日期、起止时间，地点和教师选填；错误显示在字段旁，超长内容不会直接截断。
- **明确重复范围**：默认仅一次，也可选择连续 4 / 8 / 16 周，生成可逐条编辑的具体日期。单双周、假期、调课需自行核对；编辑一条只影响该日期。
- **导入预览**：沿用 HDUHelp 只读预览接口，课程和来源提示均展示。用户主动加入草稿后可编辑、移除；课程数、日期、时间等异常不会替换已有草稿。
- **核对课表**：完全相同的条目阻止加入；时间重叠提示核对，不自动删课。每页 10 条，最多 500 条，均可翻页访问。移除有二次确认。
- **异常恢复**：未保存的表单修改、未处理的预览会阻止进入确认页。读取失败、保存失败保留当前页面草稿；离页不接受迟到响应，不跨账号持久化草稿。

当前官方校园数据包是杭州电子科技大学下沙校区，校园信息固定展示，不允许把该地图改名为另一所学校。保存前检查数据包所属校园和地点内容，缺失或不匹配时不提交。

## 一次性导入与持续同步的区别

首次配置现在是**一次性导入**。原有保存订阅接口会重新抓取并替换课表，可能覆盖刚在预览里做的编辑，因此该页面不调用它，也不绑定或保存订阅 URL。

```text
POST /api/v1/schedule-subscriptions/preview  →  只读预览
手动添加 / 加入预览 / 编辑 / 移除            →  页面草稿
GET /api/v1/campus-data                     →  校验校园地点包
PUT /api/v1/onboarding                      →  一次提交最终核对的课程
```

最终提交冻结当时的课程和学期，不重新抓订阅；只有配置完成标记、课程数、地点数与提交一致才进入首页。用户之后可在「我的」沿用原有绑定订阅功能；其同步会按订阅结果替换课表，不能用来保留手动修改。

URL 输入默认遮掩，接受预览后清除。错误提示不输出原始网络诊断或 URL。取消读取会使旧响应失效，但不承诺中断已经发出的 HTTP 请求；已发出的保存请求不能在客户端撤回，模糊失败会提示核对并可重提同一份课表。

本阶段沿用后端现有 ICS 解析能力，不新增文件/图片上传、RRULE 展开或时区转换。后端跳过事件、达到数量上限的来源提示会保留到最终核对页。预览条数代表后端实际返回的课程，不能据此宣称任意日历均完整解析。
