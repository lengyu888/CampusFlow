## 2. 产品定位与表达

**行简**面向校园事务与学习安排：把课表、待办和目标放在可理解的时间结构里，由助手生成可核对的候选，再由用户决定是否执行。

主导航使用 **今日 / 助手 / 计划 / 校园**。个人配置从头像进入；能力管理属于校园下的二级入口。品牌短句“把事情理清，把计划做成。”只用于首次介绍等低频位置，不挤占每日安排首屏。

名称是本项目工作品牌，未声明商标、域名或应用商店名称可用。后续只调整用户可见名称，不据此改仓库名、包标识、数据库路径、缓存命名空间、API 前缀和原作者记录。

### 语气与典型文案

表达具体对象、当前状态和下一步，避免“智能赋能校园”“一站式效率中枢”“开启高效人生”“已为你完美规划”等空泛或过度承诺。

| 场景 | 设计文案 | 操作 |
| --- | --- | --- |
| 今天没有定时安排，且数据已成功读取 | 今天还没有定时安排。可以先记一件事，也可以留出一点空闲。 | 记一件事 |
| 助手尚无对话 | 想先安排哪件事？可以说一个目标，或从待安排事项开始。 | 输入目标 / 查看待安排 |
| 当前筛选无任务 | 没有符合这些条件的任务。试试清除筛选。 | 清除筛选 |

“没有安排”不能覆盖加载失败；“完成”不能代替未知写入结果。未知状态使用“结果暂未确认，先核对这次操作”，保留核对入口并遵守已有写保护。普通空态不使用错误色，不因空白数据鼓励用户制造更多任务。

## 4. Things 3：借鉴列表层级，不照搬旧版外观

以下八条均来自上述图片可见内容。详情交互与完成结果另列边界，不凑成已见事实。

| 可见观察 | 行简的明确取舍 |
| --- | --- |
| 1. 首屏先是简短日期视图标题，接着是小块日历事件，再进入任务列表；没有占屏宣传图。 | 今日页以日期、当前或下一项和当天安排为主。品牌口号不作为每日大标题下的横幅。 |
| 2. 日历事件的时间与名称对齐；时间有少量色彩，正文保持中性。 | 统一时间列，标题用最强文字层级；课程地点、来源、任务归属用次级文字，不让每个字段都争夺注意力。 |

| 6. 高注意事项使用局部旗标与短时间提示，整条内容没有铺成高饱和底色。 | 冲突用明确文字和局部状态标记；不把整个日期列表染红。颜色不能成为唯一证据。 |

| 8. 大部分空间用于真实事件与任务，装饰性元素很少。 | 首屏展示数据；小插图只用于首次介绍、真实空态或少量校园入口，不夹进每一条待办。 |

## 5. Structured：借鉴时间的空间表达，控制颜色与装饰

| 可见观察 | 行简的明确取舍 |
| --- | --- |
| 1. 日期位于主时间线顶部，下方有一周日期条，选中日期有实心强调。 | 日期选择始终可见；月历只是找日期的可展开工具，不成为默认首屏的大块内容。当前代码已经收起月历，应保留。 |
| 2. 收件箱与当天时间线分成不同区域，未定时事项没有伪造开始时间。 | 无日期待办单独归入“待安排”；全天事项与缺少结束时间的事项也不能强画成有持续高度的时间块。 |
| 3. 时间标在左侧，任务标题在右；竖线与节点串起一天。 | 纸页时间轴方向使用稳定时间列与细线，减少卡片堆叠。窄屏仍以可读文字为主，不让装饰线压缩标题宽度。 |
| 4. 当前事项有更明确的标题及剩余时间；当前时刻在时间轴旁突出。 | 下一项以真实校园时区、开始与结束时间计算。只有数据足够时才显示“正在进行 / 还有多久”，不是固定演示文案。 |
| 5. 两项之间直接写出空闲间隔。 | 后续可表达“可安排时间”，但须以已加载的有效课表、任务区间与范围为依据；缺数据时写未核对，不宣称全天空闲。 |
| 6. 已完成标题带删除线，右侧状态控件出现勾选；未完成保持空心控件。 | 完成状态要同时有形状、文字或装饰变化。淡化程度不能使内容难以回看；成功反馈以实际结果为准。 |
| 7. 未来事项显示时间范围与时长，部分项目还有小型子项数量。 | 摘要展示日期、时段与任务数；细节展开后保留所有阶段及任务。只知道开始时间时，不补造时长。 |
| 8. 不同任务使用柔和类别色，但页面主体仍是白灰；底部加号为单一显著入口。 | 行简以纸白、墨绿为主体，陶土色作少量强调；避免每门课一种颜色，最多保留少量有语义的类别与状态色。 |
| 9. 待安排列表项的附加控件与主时间线加号并存，任务名称仍是视觉核心。 | 添加与安排动作有可辨文字、图标及触区。插图可以辅助认知，不替代“添加 / 确认 / 取消 / 停止”等操作标签。 |

**详情边界：** 此图没有打开任务详情，不能推断其展开高度、表单顺序或关闭后的草稿行为。行简的返回保留草稿是自身需求与现有实现约束。

**交互文字依据：** [官方 Replan 说明](https://help.structured.app/en/articles/4511874) 描述逐项处理未完成事项和跳过、撤回等入口。可借鉴“给出选择而不责备”的语气；不能据此声称本次已体验，也不能把其特定平台能力当作 ArkUI-X 保证。行简改期仍用自己的真实候选和明确确认。

**不采用：** 官网大幅营销视频与粉色宣传背景；把所有课程画成彩色胶囊；为制造轻盈感而过度降低文字对比；没有完整数据时计算空闲；未经契约保护的拖拽自动改期。

## 6. Sunsama 与 TickTick：补充负荷和日期结构

### Sunsama

画面可见的四点是：左侧把日常入口分组；中间每天一列、列头带预计总时长；任务卡内有短标签、子项和时长；右侧小时格把安排映射到一天。颜色集中在标签和日历块，背景与边框克制。

对应决定：

1. 将“预估负荷”与任务明细关联，让数字可解释；不把预计时长写成实际学习成果。
2. 任务摘要容纳所属目标、时间与状态，详细子项按需展开。
3. 日计划与待办不是两套数据；视图切换应操作同一任务 ID，保留返回位置。
4. 手机不压缩成桌面三栏。宽屏周视图可以增加空间表达，窄屏须有等价列表。

[官方每日规划说明](https://help.sunsama.com/docs/usage-guides/daily-planning/) 是检查预计工作量和调整日安排的文字依据。本次没有执行该流程。行简未来的负荷统计必须处理重叠、缺失时长和用户目标；计时与复盘要等 UX09–UX10 真实记录支持。

### TickTick

画面可见的四点是：桌面按月格定位日期；小任务条在日期格内重复对齐；选中日期有明显蓝色标记；手机保留月份与日期结构，但多项内容在较小空间内密集排列。

对应决定：

1. 借鉴清楚的日期归属与选中反馈；月历用于定位，日列表负责读取。
2. 周总览必须表达真实区间和重叠，不把现有七个日期按钮称作完整周视图。
3. 不复制截图中依赖小字、短标题和多色标签的密度；中文长课程名允许换行。
4. 不从宣传合成图推断跨端一致性、拖拽或任务编辑交互已被验证。

## 7. 三方向共同契约与差异

三种首页必须使用同一组合成数据：长课程名、明确下一项、八条安排、一项冲突、全天与无日期事项。不能通过删减某一方向的数据来营造更整洁的效果。

| 方向 | 真正的结构差别 | 借鉴与风险 |
| --- | --- | --- |
| 纸页时间轴（优先验证） | 日期与下一项在前；时间列串联安排；待安排独立；主要记录入口贴近底部操作区域。 | Things 的行密度 + Structured 的时间结构。需验证长标题、冲突说明和大字下时间列不会挤压内容。 |
| 课程手册 | 按上午、下午、晚间形成目录式分组，课程与事项像手册条目；当前位置用小书签式标记。 | 借鉴分组层级，不做仿真翻页。需验证组标题数量是否拖长首屏，跨时段任务是否表达清楚。 |
| 一日清单 | 依次是接下来、今天要做、待安排；时间为行内信息，弱化纵向轴线。 | 接近 Things 的低噪声清单。需验证课程时间与冲突不会被任务清单逻辑淹没。 |

本说明不提前宣布浏览器选优结果。最终取舍应基于 390 与 360 宽的实际观察和点击：首屏能否找到下一项、长内容是否可读、主操作是否明确、冲突与未知结果是否有恢复入口。网页 px 观察不替代原生 vp/fp 及字体缩放验收。

纸页时间轴候选的视觉决定：纸白 `#F6F4EF`、近白表面 `#FFFEFB`、正文 `#29352F`、次级文字 `#626E65`、主色 `#416454`、浅主色 `#E7EEE6`、控件边界 `#788578`、陶土强调 `#9B573B`；警示 `#886023`、危险 `#A4493E`。这是任务书指定的候选设计色，尚未修改当前 `AppTheme`。具体选中、禁用、按下及叠色状态仍需验证。

正文目标 16 fp，辅助文字 13–14 fp，页面标题 26–28 fp；页面边距 16–20 vp、间距以 4 为基数；组容器圆角约 16 vp，控件约 10–12 vp。最小触区 48 × 48 vp，允许长文和大字增高。密度靠减少重复卡片、按钮和说明实现，不靠缩字。

插图在 UX02 使用 imagegen 原创重画：安静的书页、书桌、路线等校园物件，低饱和且同一画风。大图仅限适当空态或首次介绍，约 120–160 vp；小入口图约 32–48 vp。完成、警告、录音、播报等状态用真实组件与清晰图标，不把关键文字烘焙进图片。错误、缺图和减少动态效果均有静态可用形式。

## 9. 不能在视觉改版中丢失的约束

1. **先预览后执行。** 候选、修改前后、冲突、缺失条件、取消和确认都有可读位置；删除计划保留子任务等规则不藏在省略号内。
2. **未知不是失败重试。** 已发出的写操作优先查同一次回执，不能为了原型顺畅直接重发或显示成功。
3. **时间有范围与依据。** 校园时区、跨日、全天、缺结束时间和无日期分别表达；当前缺数据不等于空闲。
4. **来源随结论可达。** 工具摘要、证据时间与出处保持可展开；来源只支持相应陈述，不为整段助手文本背书。
5. **草稿不因导航丢失。** 保留当前页内草稿和返回位置；跨重启草稿恢复由 UX03 的真实存储、账号隔离和版本规则实现，不把“暂存在变量里”描述为已持久保存。
6. **状态清楚而克制。** 未连接、未授权、加载、空、失败、离线旧数据和未知写入分开；普通空态不显示失败，旧数据不冒充刚刷新。
7. **完成不等于有效学习。** 完成任务数量、预计占用、真实计时和学习成效是不同含义。UX01 不编造专注时长或学习统计。
