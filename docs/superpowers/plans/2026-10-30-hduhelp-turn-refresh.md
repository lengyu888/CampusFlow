# HDUHelp 每轮按需刷新实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans。用户已批准方案并要求本地实施及回退，不创建提交或推送。

**Goal:** 每条消息中实际引用的 HDUHelp 资料均在本轮向上游重新获取，失败不使用旧缓存冒充当前事实。

**Architecture:** 在现有工具适配器增加异步刷新入口，以 ContextVar 隔离每轮资源结果。同轮去重、不同轮重取；相关资源并发且有总刷新预算。真实成功结果在连接未变化时加密写回单项缓存，并固定为本轮读取视图；旧接口和禁用开关保持快照读取。

**Tech Stack:** 现有 Python asyncio / httpx / LangChain 工具 / SQLite / ArkTS，不增加依赖。

**Spec:** 聊天中已批准“每轮按需刷新 + 后端异步执行 + 界面显示进度”方案；保留 BUG1、所有人工确认边界和独立文件回退。

## Global Constraints

- 不改真实 .env、令牌、账号数据或已确认课表；用合成账号与 HTTP 测试服务验证。
- 每个资源每轮成功/失败至多请求一次，不跨轮复用缓存结果；模型工具参数验证、权限检查、查询筛选及分页继续保留。
- 必需资料失败明确缺项；可选资料失败不阻止已核验的其他功能。失败不能刷新旧数据时间。
- 候选并发上限 3、单项 5 秒、整段刷新 8 秒，可配置且计入原整轮运行期限。
- 取消时回收本轮子任务；断开/替换令牌后迟到响应不能回写或进入后续工具上下文。连接校验和资源写入在同一 SQLite 事务完成。
- 对话不再调用全量同步；手动同步和令牌首次连接保留现有接口。复用 HTTP 连接并在应用退出关闭自有连接。
- 新增 AGENT_HDUHELP_AUTO_REFRESH_ENABLED=false 开关回到旧快照行为；文件回退恢复到 BUG2 前（包含 BUG1）的文件内容。

## Review Focus

- 旧缓存仍新鲜但上游变化；同轮分页与下一轮刷新。
- 三项资源并发、慢单项/总预算、其他页面可访问、取消无后台回写。
- 断开/重连、跨账号、晚响应、单项错误合并，避免串数据或刷新失败时间。
- 原生有界运行与兼容聊天工具均覆盖；非法/未授权工具参数不得触发网络请求。
- HTTP 客户端生命周期和错误消息安全、旧运行记录及 UI 进度兼容。
