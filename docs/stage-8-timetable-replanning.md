# 第八阶段：课表冲突提示与原任务改期

本轮客户端协作第八阶段，基于第七阶段提交 `97ca748c6aecf6832a566d33b9fbaf4c142d21c8`，使用独立分支 `feat/timetable-conflict-replanning`。阶段编号与仓库原有整体开发计划分别管理。

## 具体作用

例如课表更新后，14:30–15:30 的复习任务与 14:00–15:00 的课程重叠，规划页会列出双方时间。点击「按课表寻找空档，生成预览」后，会建议符合规则的新时段；用户核对并确认后，才修改原任务的时间。

- 「我的」连接或同步课表成功后，提供「去规划核对冲突」入口，并通知首页和规划刷新。
- 规划页显示按当前课表发现的冲突及核对时间；查询失败不会冒充“没有冲突”。详情和方案均完整分页展示。
- 预览展示原时间、新时间、规则和未能调整的原因。放弃预览不会改变任务；确认需要用户主动操作。
- 改期只更新原任务起止时间，保留任务 ID、标题、计划/里程碑关联、地点、提醒分钟数和完成记录；不新建第二份计划，不删除旧待办。
- 模糊网络失败后先查询同一方案的状态；不会自动重发确认。课表、任务或截止时间变化时拒绝旧方案，要求重新预览。

## 自动调整的范围

本阶段使用确定性的空档查找规则，不调用模型、不覆盖 Agent 输入草稿，也不替用户重新拆解目标：

1. 按校园时间 UTC+08:00 检查未完成任务与当前课程的区间相交；首尾相接不冲突，跨日任务可与次日课程匹配。
2. 仅移动尚未开始、具有完整起止时间且与课程冲突的任务。已完成、已结束和正在进行的任务不自动移动；无日期、缺结束时间或无效时间的待办提示手动核对，不推算时长。
3. 从原任务开始时间起的 7 天内，在每日 08:00–22:00 顺序寻找可放下完整时长的空档，不提前、不拆短，避开课程、其他明确时段的未完成任务和本批已经建议的时段。
4. 计划目标日期和里程碑截止时间共同约束新结束时间。按顺序安排，不能保证找到全局最优组合；无合适空档时保留原任务并说明原因。
5. 仅部分任务可调整时，确认只作用于预览中列出的调整项，未解决项继续保留；没有可调整项时不能确认。

不涉及地点开放时间/步行缓冲的新推断，不改变既有系统提醒能力。保留的 `reminder_minutes` 是任务配置，不能据此宣称三端系统闹钟已重新注册。

## 接口及一致性

| 接口 | 行为 |
| --- | --- |
| `GET /api/v1/planning/conflicts` | 从当前账号课表和任务读取冲突、未核对项，无写入 |
| `POST /api/v1/planning/replans`，请求 `{}` | 生成并保存独立候选记录，不修改任务 |
| `GET /api/v1/planning/replans/{id}` | 查询同一候选是否已确认，不执行改期 |
| `POST /api/v1/planning/replans/{id}/confirm`，请求 `{}` | 验证快照后原子更新本批任务时间及确认状态 |

预览有效 15 分钟。确认时对当前课表、全部任务及计划/里程碑快照重新比对；原任务或建议时段已开始也会拒绝。快照变化返回 `409 REPLAN_STALE`，过期返回 `410 REPLAN_EXPIRED`；他人或不存在的 ID 返回 `404`。已确认记录可重复查询/确认，但不会再次改动任务，即使随后课表再次变更。

生产配置的账户与规划存储使用同一 SQLite 文件。新服务以同一数据库连接和 `BEGIN IMMEDIATE` 读取最新数据、批量更新与记录确认，保证全批提交或回滚；支持跨进程数据库锁。内存测试模式使用同一进程内两仓库锁。未重构旧 Agent `create` 提案通路，这些确认保障特指本阶段的新改期接口。

客户端确认中/结果未知时禁止生成另一份方案或放弃确认身份；切到其他页会失效只读结果及普通预览，确认结果未知则保留方案 ID 供返回后查询。销毁账号页面后旧回调不能更新新账号界面。应用关闭后不持久化客户端预览，重新进入会核对服务端当前任务。
