# UX04：今日、轻记录、课程路线与课内安排

## 用起来有什么变化

- 今日先看到正在进行或接下来的安排。早些时候可以展开，过时但未完成的任务仍可见；没有结束时间不会被猜成已经结束。
- 在首页点“记一件事”打开轻表单，返回仍保留输入。复用计划页的同一表单、草稿和确认控制器，避免两个入口各保存一份。旧草稿与未知提交需要先处理，空档建议不会覆盖它们。
- 输入“明晚八点复习一小时”后主动提取，会显示完整日期、20:00 和 60 分钟；可以逐项改。“下午”“下课后”等不补造时刻。原文与不支持的部分保留，主动点按钮才能交给助手。
- 空档仅根据成功读取且有效的课程/任务时段计算。0/5/10/15 分钟缓冲由用户选择，默认 0；不是通勤估计。点建议只填草稿，不创建任务。
- 课程路线带着完整课程、校园和来源进入。只有唯一真实地点才预选终点；有多个匹配让用户选，找不到则展示原地点。起点由用户选择，不猜当前位置。

## 可在上课时完成

每项任务的“可在上课时完成”默认关闭，旧数据也是关闭。开启只是允许进一步核对，不代表自动通过。

1. 服务端预览返回精确候选 ID、课程原信息、重叠区间和任务/课表版本。
2. 预览逐项显示学校、校区、日期、课程时段与实际重叠；用户选择“仍这样安排”，然后确认整份变更。
3. 确认携带对应候选和审阅摘要。服务端同一事务再次检查，将任务、课程确认和执行回执一起保存。
4. 重复请求返回原回执；不能通过更换同名任务、遗漏一门课程、课程改后再改回等方式复用旧同意。
5. 当前状态区分已确认课内安排、待重新核对、未许可冲突、未完整核对。课程/本任务变化会使旧确认失效。其他任务互撞、截止、身份与版本限制仍保留。
6. 只关闭许可时允许撤回；原时段保留并明确提示仍需调整，不把它说成没有冲突。模型工具没有开启许可的参数。

已接受的课内安排不被规则改期自动移走；新出现或失效的重叠保留待核对。助手内逐候选许可界面在 UX05 继续接入，周视图与扫描说明在 UX06 精修。

## 主要实现

- `HomePage`、`FreeWindows`：来源独立读取、时间线分组、完整时段空档与建议。
- `Index`、`PlanCenterPage`：共享轻表单、原计划详情栈恢复、可编辑日期/时长、完整草稿、精确回执。
- `QuickCaptureParser`：范围明确的确定性解析，详见 [支持范围](ux-04-capture-parser.md)。
- `CourseRouteIntent`、`RoutePage`：课程来源与校园约束、唯一/多义匹配、按地点 ID 查询及回包核验。
- `CourseReview`、`CourseReviewPanel`、`PlanningActionPanel`：真实候选、交集、确认和回执映射校验。
- 后端 `course_policy`、`ActionService`、`AccountStore`、`CampusStore`、规则改期：SQLite 单调版本、原子确认与旧入口保护。
