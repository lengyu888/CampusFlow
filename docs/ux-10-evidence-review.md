# UX10｜有依据的日／周回看

「回看」把已经记录的事实收拢为三个数字：本期完成且目前仍完成的事项、当前尚未安排开始时间的待办、落在本期的已同步专注时长。首页可看今天，计划页可看所选日期的一周；每组都可展开查看来源。无需配置模型即可使用。

## 使用方式

1. 从首页「回看今天」或计划页的回看入口进入。切换日／周和日期，范围采用校园时间 UTC+08:00，周一至下周一，左闭右开。
2. 查看三个事实和对应明细。已完成时间缺失的旧事项单列；未知区间不补时间；本机待同步记录单独提示，不混入服务端总时长。
3. 可写一句感受并保存到本机，最多500个Unicode字符。切日期、返回、跳到任务或助手前先保护当前输入。存储失败保留输入，并提供管理已有感受的入口。与其他草稿共享20个槽位，不自动挤掉旧内容。
4. 勾选要交给助手的事实，感受需另外主动选入；预览准确内容后再交接。助手保留原有输入，将回看作为可采用或追加的建议，不自动发送或修改安排。
5. 待安排事项只跳转精确任务，由既有编辑候选和确认流程处理。回看页不会自行给下周排计划。

## 统计口径

| 内容 | 纳入规则 | 明确边界 |
| --- | --- | --- |
| 本期完成 | 当前状态仍为完成，完成时间落在范围内 | 恢复未完成或删除后不计；再次完成按新时间归期 |
| 完成依据 | 有操作编号时核验同账号、同任务的已生效完成回执；旧记录使用有效完成时间 | 缺时间另列，不用创建时间替代 |
| 当前待安排 | 当前未完成且没有开始时间 | 不称为当日或周末的历史待办数 |
| 专注时长 | 未删除记录中已确认的计时片段，与本期交集按比例分配 | 未封段、本机队列、未知区间不计；计时不等同于有效学习 |
| 跨日片段 | 保留原始微秒时间，以精确商余算法分配整数毫秒 | 相邻日期之和等于整段，少于1毫秒的份额可为0且保留来源 |
| 待核对区间 | 按开始标注所在日期归期 | 结束未知或时钟回退时不推算时长 |

这是读取时刻的当前资料，不是历史状态完整还原。页面保留读取时间；同范围刷新失败时明确显示旧资料，换日期或换账号不复用旧内容。没有记录不表示没有学习；不生成效率百分比、改期次数或惩罚式排名。

## 接口和本地兼容

新增只读 `GET /api/v1/reviews?period=day|week&anchor=YYYY-MM-DD`，沿用账号鉴权。后端在同一个读事务内冻结任务、确认片段、未知区间、记录和完成回执；返回包含范围、读取时间、统计、来源、快照摘要的白名单结构。前端逐项核对身份、日期、明细和总数。摘要用于标识该次快照，不等于独立证明数据库没有遗漏。

查询和响应有明确上限：任务10000、相关来源5000、JSON 2 MiB；超过上限整次报错，不截取部分数据冒充完整统计。SQLite增加时间表达式索引，不改写旧计时片段。索引和接口不会向模型发请求。

本机新增 `review-note` 草稿类型，复用现有账号／服务隔离、原子文件和版本校验；仅保存日／周、日期、时区及感受文字，不缓存报告、任务标题或凭据。退出账号或明确清除本机草稿会一并移除；重启后可在对应日期恢复已保存感受。回退到不认识该草稿类型的旧客户端前，先处理本机草稿，避免旧版本将文件视为不兼容；不承诺跨旧版本降级无损。
