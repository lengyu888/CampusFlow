## 具体作用与使用方法

1. 联网登录，向 Agent 发送问题。收到有效回答后，页面显示本机保存结果；磁盘失败不会把成功回答变成发送失败，也不会重复调用模型。
2. 在线打开历史会话，会保存完整的用户/助手文字。服务不可用时，可继续读取已有本机副本；没有缓存的会话会明确提示需要联网。
3. 关闭 App 后断网重开，在登录页点击“离线查看本机对话”。该入口只显示缓存，不登录账号、不调用接口、不恢复待确认提案。
4. 离线的“移除本机副本”只清此设备缓存，之后可以联网重新下载。在线“删除”在服务端确认删除或明确返回不存在后，清本机副本并重置活动 Agent 会话。
5. 退出账号即关闭在线与离线入口并清理本机记录；网络登出失败也不会恢复本地登录。清理失败会提示，并提供重试清理入口。

第 3 项是待三端设备执行的使用场景；本机只验证了相同存储逻辑在重新创建实例后读回，尚无 App 冷启动实测。

## 保存与隔离规则

- 以服务地址和 `user_id` 组成账号范围，仅保留最近一个账号。同账号重新登录保留；更换账号或服务范围时替换旧缓存。
- 使用 `context.filesDir` 下的应用私有文件。文件只包含账号范围、显示名、会话摘要、用户/助手正文与时间及删除标记，不序列化认证令牌、API Key 配置、原始工具响应或提案对象。聊天正文按原文保存，不做敏感文本识别脱敏。
- 不额外设置 PIN、生物识别或文件内容加密。离线回看依赖设备锁屏和应用沙箱，登录页明确说明解锁设备的人可以查看；它不是服务端认证会话。
- 最多保留 20 个完整会话；JSON 使用保守的 UTF-8 容量估计控制在 2 MiB 内。容量不足时移除完整旧会话；单个会话超限则不保存并提示，绝不截断正文伪装为完整副本。
- 文件异步串行写入：临时文件 → 核对写入字节数 → fsync/关闭 → rename 替换。短写或替换失败保留旧文件。损坏、未来版本或权限错误不会被当作空缓存覆盖。
- 账号代次和页面请求版本阻止旧账号、旧页面响应写回。删除标记持久化，防止超时请求的晚到结果重新生成已删除的本机副本。
- 删除等待中可以切换页面，已成功的删除仍会清理原账号缓存并通知 Agent；切换账号则不会误清新账号。聊天与删除同时发生时，页面阻止新请求和重复删除。

完整工具轨迹、待确认提案、失败发送草稿及继续旧会话不在本次离线恢复范围。服务端“删除后仍在执行的旧 chat 可能再次写入”问题尚未改后端；本次删除标记保护本机副本，不能作为服务端一致性修复声明。

## 待三端验收与语音交接

三端分别验证：联网成功对话 → 关闭进程 → 断网重开 → 离线入口完整回看 → 恢复联网；同账号重登、换账号、换服务、退出清理；删除中切页、连续删除、超时晚响应；长表格/代码原文复制、容量超限及读写失败反馈。每端记录设备、系统、SDK、安装包提交与实际截图，未运行项保持“未执行”。

文件 API 选择依据是 [ArkUI-X 官方 fs 文档](https://github.com/arkui-x/docs/blob/master/zh-cn/application-dev/reference/apis/js-apis-file-fs.md)，相关方法列明 Android/iOS 支持；仍需目标 SDK 和三端设备证明实际可用。

当前源码没有完整 ASR/TTS 链路，鸿蒙模块尚未申请麦克风权限。下一阶段适合与 E 线先在鸿蒙设备上接入“授权录音 → 识别文字可编辑 → 用户发送 → 复用现有 Agent → 最终回答可播报/停止”。可参考 [Huawei ASR API V13](https://developer.huawei.com/consumer/cn/doc/harmonyos-references-V13/hms-ai-speechrecognizer-V13) 与 [TTS API V13](https://developer.huawei.com/consumer/cn/doc/harmonyos-references-V13/hms-ai-texttospeech-V13)，它们是旧版鸿蒙能力依据，不代表已验证本工程 API 24，也不能推断 Android/iOS 支持。先验证鸿蒙设备能力，再决定平台适配；本阶段未添加假录音按钮或语音占位实现。
