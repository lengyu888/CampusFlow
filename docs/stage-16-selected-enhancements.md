# 第十六阶段：模型适配、主动偏好与有出处的校园资料

基线：第十五阶段 `feat/stage-15-native-capabilities`。这是本轮最后一个阶段；按最新要求，第十七阶段及真实模型评测不开展。

## 有什么用

1. **模型按能力选择。** Agent 页面读取服务端目录，展示供应商、工具/增量回答/推理声明、推荐模型和不可用原因。服务端在新运行落库及调用模型前再次校验；明确拒绝可重选，未知网络结果仍按原运行 ID 核对。旧会话中已移除的模型仍按历史名称显示，不偷偷换成新模型。
2. **学习习惯由用户掌握。** 个人设置可主动填写单次专注、休息、每日学习目标和偏好时段，查看保存值与未保存草稿，明确保存开关、修改或确认删除。默认不启用，不从聊天推断个人习惯。偏好作为下一次请求的建议，优先服从本轮明确要求、课程、已有安排与截止日期。
3. **校园资料能找到依据。** 校园页可直接检索精选官方参考资料，不需要模型密钥。结果有标题、原文小节、短摘录、链接和资料核对日期；Agent 的只读工具也能查询并显示来源。无命中、未支持校区、读取失败分别说明，不用演示内容或模型猜测补答案。

## 具体实现

### 模型

保留原来的两个 DeepSeek 模型与个人 Key 路径；额外模型通过 `MODEL_CATALOG_JSON` 显式注册标准 OpenAI 兼容协议，由各自 `key_env` 指定服务进程凭据。用户个人 DeepSeek Key 不会被转发给额外供应商。目录响应不返回密钥、环境变量名或服务地址。配置了能力和凭据仅代表“配置就绪”，不代表模型真实质量或在线可用性已验证。

两个对话入口均使用相同目录。新持久运行保留 DeepSeek 思考续轮所需的 `reasoning_content`，但不展示或保存私人推理；标准兼容接口不携带 DeepSeek 扩展。旧 LangChain chat 使用 DeepSeek non-thinking 模式，避免框架消息转换丢失思考字段导致工具续轮失败。兼容供应商按声明发送 `max_tokens` 或 `max_completion_tokens`，不依赖 SDK 隐式改名。

配置实例、能力与凭据边界见 [模型服务说明](model-providers.md)。本阶段未新开任何付费供应商、未配置真实测试密钥、未发起真实模型调用。

### 偏好

接口为 `GET/PUT/DELETE /api/v1/learning-preferences`，写入必须携带 `base_revision`、UUID `operation_id` 与完整的五项偏好。SQLite 在同一事务完成版本比较、更新与回执，失败回滚；相同操作重试返回当前快照，不再次执行旧写入。跨连接并发只允许一个旧版本写入成功。

回执不保存旧偏好正文。删除恢复默认值并停用，同时清除旧回执内容摘要，保留操作标识墓碑，拒绝迟到旧保存恢复已删除内容。关闭/删除只影响后续请求，不撤回已开始的运行或旧回答，也不宣称数据库物理介质已安全擦除。

客户端对未知保存结果保留原 UUID/请求体，允许原操作重试或读取当前值；读取当前值本身不被当作原写入成功证据。版本冲突后保留草稿，先核对最新值；清除与放弃草稿分别明确确认。页面切换/账号切换后的迟到回包不得改写新页面。

### 校园知识

当前语料仅为 2026-10-18 核对的 4 个杭电官方页面：

- [图书馆校外访问](https://tsg.hdu.edu.cn/xwfw/list.htm)
- [校园网络资源使用说明（2021年页面）](https://nicin.hdu.edu.cn/2021/0519/c6352a134647/page.htm)
- [信息公开指南](https://xxgk.hdu.edu.cn/8784/list.htm)
- [杭电文库](https://tsg.hdu.edu.cn/hdwk/list.htm)

这是明确范围的本地词法检索，最多返回三条，不是全校百科或向量库。不查询当日开放、实时座位、考试、余额、密码或账号激活。摘录之外的摘要为整理后的转述；核对日期不等于发布日期或生效期限，以学校最新原文为准。出处详情 API 读取已收录条目，不是在用户点击时重新抓取学校页面。遇到跳转登录的资料未绕过登录、未猜其内容。

`search_campus_knowledge` 归属校园地点助手的只读校园资料权限。直接校园资料查询只读公开资料；Agent 工具仍受 Skill 启停控制。来源卡片来自服务端真实检索结果，不宣称整段模型自由回答已经逐句验证。知识正文是资料，不能作为工具执行或系统指令。

## 验证

- 学习偏好 26 项离线检查通过，包含真实 SQLite 并发、事务回滚、删除后防恢复、HTTP 身份验证、真实 Agent 运行/旧 chat 提示词输入（模型响应使用离线替身）。
- 模型专项使用真实 SDK 与离线 HTTP/SSE transport 检查实际请求参数、工具续轮、独立供应商 Key 隔离和运行前拒绝，不发送外网模型请求。
- 9 份真实 HTTP/SQLite 回包通过生产 ArkTS 模型目录、偏好、知识结果校验器；包含重试、清除、命中/无命中/未支持校区，原文 URL 保持一致。
- 最终完整服务端离线测试 **594 通过，2 项真实模型集成测试按标记排除**；客户端 **593 通过、1 项缺 JDK 明确跳过、0 失败**；静态检查 **57 个 ArkTS/TS 文件、17 个配置通过**，全部变更 Python 文件 Ruff 与 diff 检查通过。模型专项 37 项、知识专项 34 项包含在服务端总数中，不重复加总。

ArkTS 逻辑提取执行、模拟生命周期和静态工程检查不代替原生编译/设备操作。本轮没有安装原生环境；实际三端文本对话、本地历史、语音、权限、系统提醒送达以及真实模型回答质量仍由学长完成设备/在线验收。第十五阶段的 1 项 Java 辅助测试因没有 JDK 继续明确跳过。

## 演示顺序（待在已准备的设备与账号上执行）

先录入课表并确认导入预览；进入今日/规划查看课程和任务；设置明确学习偏好；在 Agent 选择可用模型提出学习安排，查看真实工具进度、来源及待确认提案；确认后查看规划与系统提醒状态；修改课表，展示冲突与重新规划；最后演示校园资料出处、取消/恢复运行和重启后本地历史。涉及云模型/系统语音/通知的演示须在已有设备环境上验收，不把本地原型画面当作原生截图。
