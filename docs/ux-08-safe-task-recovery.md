# UX08：误点完成后，核对再恢复

## 用户能做什么

未完成事项仍可直接勾选完成。已完成任务旁保留“恢复未完成”入口；无需赶在短暂提示消失前点击。恢复先展示当前任务、时段与冲突，明确确认后才改变状态。

恢复不会回退整行任务。比如完成后在另一端改了标题和时间，需要读取最新内容重新核对；成功恢复只改变完成状态，保留已经修改的标题、时段、地点和归属。已删除任务不能从旧回执重建。

“可在上课时完成”设置保持原值。恢复后将重新进入待办，因此存在课程重叠时需要再次查看具体课程和重叠时段，明确同意本次安排；原来同意过不等于新课表仍然合适。不开启此设置的任务仍需避开课程，任务互撞和截止检查继续有效。

旧版已完成任务如果没有可核验的完成记录，会说明原因，不提供会覆盖当前状态的伪撤销。删除计划、整批改期、导入课表和专注记录都不属于这次有限恢复。

## 完成与恢复的接口

- `POST /api/v1/tasks/{task_id}/status-operations`：完成，或创建恢复预览。每次明确操作使用固定 UUID 与当前任务版本。恢复还指明本次完成的原操作 ID。
- `GET /api/v1/task-status-operations/{operation_id}`：只读查结果。
- `POST /api/v1/task-status-operations/{operation_id}/confirm`：确认原恢复预览，携带准确课程确认；不偷偷按新数据重写预览。
- `POST /api/v1/task-status-operations/{operation_id}/cancel`：取消尚未应用的恢复预览。已经应用则返回原回执。

响应 `contract_version=1`，回执保留操作、任务、前后版本与状态、应用时间及课内确认引用。回执说明“这一笔操作曾经生效”，当前任务列表必须另外刷新。

旧 `PATCH completed:true` 经同一状态内核处理，真正从未完成变为完成时生成凭据；已经完成的旧数据不会被补造一次完成。旧 `PATCH completed:false` 明确返回 `TASK_RECOVERY_PREVIEW_REQUIRED`，提示升级到预览确认流程。

## 版本、持久化与错误

完成和恢复与回执一起写入事务。任务版本由实际任务更新推进，标题、时段、归属、旧写入、批量改期等相关路径均受保护。恢复精确绑定当前这一次完成；完成 A、恢复 A、再次完成 B 后，A 的凭据不能恢复 B。

客户端先保存固定请求，再发出写入。超时不等于失败，先按原 ID 查询；未查到时由用户明确重试同一笔内容。确认结果未知后，查询到仍待处理，用户可以明确取消；最终以服务器仲裁结果为准。关闭面板、切换页面或读到相同状态均不冒充取消或成功。

本机操作记录与用户输入草稿分开，按账号与服务范围保存，不含模型密钥或会话全文。清除数据及退出时明确处理未结清操作；换号或旧响应迟到不允许写进新账号界面。某项任务待核对时，仅阻挡涉及该任务的冲突操作，其他内容仍可查看。

数据库迁移保留原任务 ID、内容和状态，新增完成引用与状态操作表并更新版本触发器。旧数据引用为空；没有自动回填虚构回执。回滚应用版本前须评估新增协议与旧客户端恢复限制，不能通过删表抹掉已经执行的操作事实。
